# React 밖의 값과 1분 타이머

6-6에서 하우스 목록 맨 위에 "미전송 2건 · 마지막 동기화: 5분 전"을 띄우며 쓴 것들이다. 화면이 "바뀌면 다시 그리기"를 하려면 React가 그 값이 바뀐 것을 알아야 한다. 값이 어디 있느냐에 따라 방법이 다르다.

| 값 | 어디 있나 | 바뀐 것을 React가 아는 방법 |
|---|---|---|
| 기록, 미전송 수, 이름 표 | IndexedDB | `useLiveQuery` (Dexie가 알려 줌) → [[2026-10-22-IndexedDB와-Dexie]] 4번 |
| 지금 화면, 알림 글 | React 안 (`useState`) | `setScreen(...)`을 부르면 → [[2026-10-22-React-state와-이벤트]] |
| 마지막 동기화 시각 | localStorage | **알려 주는 것이 없다.** 그래서 직접 알리고 `useSyncExternalStore`로 받는다 (1번) |
| 지금 시각 | 어디에도 없음 (계속 바뀜) | 1분마다 `useState`에 넣는다 (2번) |

## 1. `useSyncExternalStore`: React 밖의 값을 화면에 묶기

localStorage는 값이 바뀌어도 아무에게도 알리지 않는다. `localStorage.getItem(...)`을 화면에서 그냥 읽으면, 동기화가 끝나 값이 바뀌어도 화면은 다른 이유로 다시 그려질 때까지 옛 값을 보여 준다.

그래서 값을 쓰는 쪽(`syncService.ts`)이 "바뀌었다"고 알리는 창구를 만들었다.

```ts
// data/syncService.ts
const lastSyncedListeners = new Set<() => void>()

export function getLastSyncedAt(): string | null {
  try {
    return localStorage.getItem(LAST_SYNCED_KEY)
  } catch {
    return null
  }
}

export function subscribeLastSyncedAt(listener: () => void): () => void {
  lastSyncedListeners.add(listener)
  return () => lastSyncedListeners.delete(listener)
}

function writeLastSyncedAt(time: string): void {
  try {
    localStorage.setItem(LAST_SYNCED_KEY, time)
  } catch {
    // 못 적으면 화면에 "동기화 전"으로 보일 뿐이다
  }
  lastSyncedListeners.forEach((listener) => listener())
}
```

- **구독(subscribe):** "바뀌면 이 함수를 불러 줘"라고 등록한다. 돌려받은 함수를 부르면 등록을 푼다
- **알림:** 값을 쓴 뒤 등록된 함수를 모두 부른다
- Java의 관찰자 패턴(옵저버)과 같다

  ```java
  private final Set<Runnable> listeners = new HashSet<>();

  public Runnable subscribe(Runnable listener) {
    listeners.add(listener);
    return () -> listeners.remove(listener);   // 등록 풀기
  }

  private void write(String time) {
    prefs.put(KEY, time);
    listeners.forEach(Runnable::run);          // 알림
  }
  ```

  Spring이라면 `ApplicationEventPublisher.publishEvent(...)`와 `@EventListener`로 하는 일이다

화면 쪽은 React에 들어 있는 훅 하나로 받는다.

```ts
// data/recordRepository.ts
import { useSyncExternalStore } from 'react'

export function useLastSyncedAt(): string | null {
  return useSyncExternalStore(subscribeLastSyncedAt, getLastSyncedAt)
}
```

- **첫 인자(구독 함수):** React가 화면이 뜰 때 자기 "다시 그리기" 함수를 넘겨 등록하고, 화면이 사라질 때 돌려받은 함수로 등록을 푼다. `useEffect`의 정리 함수와 같은 짜임이다 → [[2026-10-22-React-state와-이벤트]] 5번
- **둘째 인자(값 읽기 함수):** 그릴 때마다, 그리고 알림이 올 때마다 부른다. 값이 지난번과 같으면(`===`) 다시 그리지 않는다
  - 그래서 읽을 때마다 **같은 값이면 같은 것을 돌려줘야** 한다. 글자(`string`)와 `null`은 내용이 같으면 `===`가 `true`라 괜찮다. 읽을 때마다 `{ time: ... }` 같은 새 객체를 만들어 돌려주면 매번 "바뀌었다"가 되어 화면이 끝없이 다시 그려진다 (Java의 `equals`가 아니라 `==`로 비교한다고 생각하면 된다)
- 이름이 길지만 뜻은 "React 밖(external)에 있는 저장소(store)와 맞춰(sync) 쓴다"이다
- 화면은 `useLastSyncedAt()`만 부른다. localStorage에 있다는 것은 모른다 (`CLAUDE.md` 아키텍처: 화면은 `recordRepository`만 부른다)

### 왜 IndexedDB에 두지 않았나

마지막 동기화 시각을 IndexedDB에 두면 `useLiveQuery`로 바로 묶을 수 있다. 하지만 값 하나 때문에 표를 새로 만들고 Dexie 버전을 3으로 올려야 한다. 비슷한 값인 "마지막으로 받은 시각"(`buchu-farm:last-received-at`)도 이미 localStorage에 있어서, 같은 곳에 두고 알림만 더했다.

## 2. 1분 타이머: "5분 전"이 저절로 늘어나게

"5분 전"은 마지막 동기화 시각과 **지금 시각**의 차이다. 마지막 동기화 시각은 그대로여도 지금 시각이 늘어나니 글자가 바뀌어야 한다. 그런데 React는 시간이 흐른 것을 모른다. 그래서 1분마다 지금 시각을 `useState`에 넣어 다시 그리게 했다.

```tsx
// App.tsx
const [now, setNow] = useState(() => nowTimestamp())
const today = todayInKorea(new Date(now))

useEffect(() => {
  const tick = () => setNow(nowTimestamp())
  const timer = setInterval(tick, 60_000)
  document.addEventListener('visibilitychange', tick)
  return () => {
    clearInterval(timer)
    document.removeEventListener('visibilitychange', tick)
  }
}, [])
```

- **`setInterval(함수, 밀리초)`**: 그 간격마다 함수를 계속 부른다. 한 번만 부르는 `setTimeout`(알림 3초)과 짝이다. `clearInterval`로 멈춘다. Java의 `ScheduledExecutorService.scheduleAtFixedRate(...)`와 `cancel()`, Spring의 `@Scheduled(fixedRate = 60000)`
- **`60_000`**: 숫자 가운데 `_`는 읽기 쉽게 끊어 쓴 것이다. `60000`과 같다. Java도 `60_000`이라고 쓸 수 있다
- **`useState(() => nowTimestamp())`**: 처음 값을 함수로 넘기면 처음 한 번만 부른다 → [[2026-10-23-6단계-코드-읽기]] 7번의 `useState(getCurrentUser)`와 같다
- **`[]`**: 처음 한 번만 타이머를 건다. 정리 함수가 타이머를 멈추므로 개발 모드의 "실행 → 정리 → 실행"에도 타이머가 둘이 되지 않는다
- **`visibilitychange`에도 `tick`을 거는 이유:** 앱이 뒤에 있거나 폰 화면이 꺼져 있으면 폰이 타이머를 멈추거나 늦춘다. 밤새 꺼 두었다가 아침에 열면 `now`가 어젯밤 시각인 채로 최대 1분을 보낸다. 화면으로 돌아오는 순간 바로 바꾸면 그런 일이 없다
- **"오늘"도 `now`에서 뽑는다.** 전에는 그릴 때마다 `todayInKorea()`로 그 순간의 날짜를 읽었다. 이제 1분마다(그리고 돌아올 때) 다시 그려지니 앱을 켜 둔 채 자정이 지나도 1분 안에 날짜가 바뀐다
- 지금 시각은 여전히 `domain/today.ts`의 `nowTimestamp()`로만 읽는다 (`CLAUDE.md`: 현재 시각은 한 곳에서만 읽음)

1분마다 App 전체가 다시 그려진다. 25동 계산을 다시 하지만 아주 작은 일이라 폰에서도 느려지지 않는다.

## 3. "N분 전" 글자: 순수 함수로 따로

```ts
// pages/labels.ts
export function relativeTime(time: string, now: string): string {
  const minutes = Math.floor((Date.parse(now) - Date.parse(time)) / 60_000)
  if (minutes < 1) return '방금'
  if (minutes < 60) return `${minutes}분 전`
  const hours = Math.floor(minutes / 60)
  if (hours < 24) return `${hours}시간 전`
  return `${Math.floor(hours / 24)}일 전`
}
```

- 지금 시각을 인자로 받는다. 함수 안에서 시각을 읽지 않아서 테스트에서 고정할 수 있다 (`harvestCalc`와 같은 방식 → [[2026-10-22-Vitest-테스트와-순수-함수]])
- `Date.parse(...)`: 시각 글자 → 밀리초 숫자. 빼면 두 시각 차이(밀리초)
- `Math.floor`: 소수점 아래를 버린다. 59초는 0분 → "방금", 1시간 59분은 1시간 → "1시간 전". Java의 `Math.floorDiv`
- 폰 시각이 뒤로 바뀌어 차이가 음수여도 `minutes < 1`이라 "방금"이다
