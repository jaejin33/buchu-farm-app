이번 세션을 마무리하며 `docs/`를 정리한다. 추가 요청 사항: $ARGUMENTS

## docs/ 구조

```
docs/
├ 진행기록.md     현재 상태 요약 (단계가 바뀔 때만 고침)
├ 결정기록.md     날짜별 결정 기록 (추가만 함)
├ 현장/           설문 결과, 통화 메모, 영농일지에서 알게 된 것
└ 학습/           이번 세션에 설명한 개념 노트
```

## 순서

1. 이번 세션의 대화와 `git log`, `git diff`를 보고 오늘 한 일을 파악한다
2. **결정이 생기거나 바뀌었으면** `docs/결정기록.md` 맨 아래에 추가한다. 형식:

   ```
   ## YYYY-MM-DD 결정 제목
   - 결정: 무엇을 하기로 했는지
   - 이유: 왜
   - 이전: 원래 어떻게 하려고 했는지 (바뀐 경우)
   ```

3. **개념을 설명한 내용이 있으면** `docs/학습/YYYY-MM-DD-주제.md`로 저장한다. Spring에 대응되는 개념이 있으면 함께 적고, 대응이 없으면 없다고 적는다
   - 읽는 사람은 Spring·Java·HTML만 안다고 보고 자세히 쓴다. 노트에 나오는 JS/TS 문법(화살표 함수, 전개 문법, `===` 등)도 처음 보는 것으로 보고 짚어 준다
   - Java·Spring 대응은 말로만 하지 말고 짧은 Java 코드나 대응표로 보여 준다
4. **진행 단계가 바뀌었을 때만** `docs/진행기록.md`의 현재 상태 부분을 고친다
5. 관련 노트끼리 옵시디언 `[[노트 이름]]` 형식으로 연결한다

## 규칙

- 기존 내용은 지우거나 고쳐 쓰지 않는다. 추가만 한다 (`진행기록.md`의 현재 상태 부분은 예외)
- 내가 말하지 않은 농사 사실을 지어내지 않는다. 추측은 "확인 필요"로 표시한다
- 영농일지 사진, 정산 문자, 일하는 분들의 이름·일당, 매출 금액은 적지 않는다
- 정리할 내용이 없으면 없다고만 말한다. 억지로 노트를 만들지 않는다

## 마지막

바꾼 파일과 내용 요약을 보여주고, 커밋할지 물어본다. 승인하면 `docs: <요약>` 메시지로 커밋한다.
