# 5단계 코드 읽기: 배포와 PWA

5단계(Vercel 배포)와 5.1단계(PWA)에서 바뀐 파일을 읽는다. 화면 코드는 거의 그대로이고, **설정 파일과 아이콘**이 대부분이다. 개념은 [[2026-10-23-PWA와-서비스-워커]], [[2026-10-23-https와-Vercel-자동-배포]].

## 1. 파일 지도

```
vite.config.ts          ← PWA 설정 (vite-plugin-pwa)
index.html              ← 탭 아이콘, 아이폰 아이콘, 상태 표시줄 색
public/
├ icon.svg              ← 아이콘 원본 (직접 그림)
├ favicon.ico           ┐
├ pwa-64x64.png         │
├ pwa-192x192.png       │ icon.svg에서 만든 PNG (한 번 만들고 레포에 넣음)
├ pwa-512x512.png       │
├ maskable-icon-512x512.png
└ apple-touch-icon-180x180.png ┘
src/pages/RecordForm.tsx ← PC에서 날짜 상자가 안 열리던 것 수정

npm run build →  dist/manifest.webmanifest, dist/sw.js, dist/registerSW.js 가 새로 생김
```

Vercel 배포 자체는 코드가 없다. Vercel 화면에서 GitHub 레포를 연결한 것뿐이다.

## 2. `vite.config.ts`

```ts
import { VitePWA } from 'vite-plugin-pwa'

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'autoUpdate',
      includeAssets: ['favicon.ico', 'icon.svg', 'apple-touch-icon-180x180.png'],
      manifest: {
        name: '부추 하우스',
        short_name: '부추 하우스',
        lang: 'ko',
        display: 'standalone',
        start_url: '/',
        theme_color: '#12a150',
        background_color: '#f2f4f6',
        icons: [ /* 64, 192, 512, maskable 512 */ ],
      },
    }),
  ],
})
```

- **`plugins` 배열:** Vite가 빌드할 때 차례로 거치는 단계들이다. `react()`는 JSX를 JS로 바꾸고, `VitePWA()`는 앱 소개 파일과 서비스 워커를 만든다. Gradle의 `plugins { id 'org.springframework.boot' }`처럼 빌드에 기능을 더한다
- **`registerType: 'autoUpdate'`:** 새 버전을 받으면 묻지 않고 바꿔 끼운다. 화면을 저절로 새로 고치지는 않는다 → [[2026-10-23-PWA와-서비스-워커]] 3번
- **`includeAssets`:** JS·CSS·HTML은 알아서 미리 받아 두고, 그 밖에 받아 둘 파일을 적는다. 인터넷이 끊겨도 아이콘이 보이게
- **`manifest`:** 그대로 `manifest.webmanifest` 파일이 된다
  - `short_name`: 홈 화면 아이콘 아래 이름. 길면 잘린다
  - `display: 'standalone'`: 주소창 없이 앱처럼
  - `theme_color`: 폰 맨 위 상태 표시줄 색 (주 색 초록, `index.css`의 `--primary`)
  - `background_color`: 앱이 뜨기 전 잠깐 보이는 바탕 (`index.css`의 `--bg`)
  - `purpose: 'maskable'`: 안드로이드가 기종마다 동그라미·둥근 네모로 잘라 쓰는 아이콘이다. 잘려도 보이게 잎을 가운데(지름의 80% 안)에 모아 그렸다

빌드하면 `PWA v2.0.0 ... precache 12 entries`가 찍힌다. 앱 파일 12개를 처음 열 때 받아 둔다는 뜻이다.

## 3. `index.html`

```html
<link rel="icon" href="/favicon.ico" sizes="48x48" />
<link rel="icon" type="image/svg+xml" href="/icon.svg" />
<link rel="apple-touch-icon" href="/apple-touch-icon-180x180.png" />
<meta name="theme-color" content="#12a150" />
```

- `favicon.ico`와 `icon.svg`: 브라우저 탭 아이콘. 둘 다 적으면 브라우저가 쓸 수 있는 것을 고른다
- **`apple-touch-icon`: 아이폰 홈 화면 아이콘.** 아이폰은 manifest의 아이콘을 쓰지 않고 이 줄을 본다. 두 폰을 모두 지원해야 해서 따로 적었다
- 빌드하면 플러그인이 `<link rel="manifest">`와 `<script src="/registerSW.js">`를 `</head>` 앞에 더해 준다. 직접 적지 않는다

## 4. 아이콘 (`public/`)

- `public/` 폴더의 파일은 빌드할 때 손대지 않고 `dist/`에 그대로 복사된다. Spring Boot의 `src/main/resources/static/`과 같다
- `icon.svg`는 512×512 초록 바탕에 흰 부추 잎 다섯 줄이다. SVG는 그림을 글자(좌표)로 적은 파일이라 편집기로 열어 고칠 수 있다
- PNG는 `@vite-pwa/assets-generator`로 한 번 만들었다. 이 도구는 프로젝트에 설치하지 않았다(`npx`로 한 번만 실행). **아이콘을 바꾸려면 `icon.svg`를 고치고 PNG를 다시 만든다**
- Vite 기본 로고(`favicon.svg`, 보라색 번개)는 지웠다

## 5. `RecordForm.tsx`: PC에서 날짜 상자

배포 뒤 PC로 열어 보니 날짜 상자를 눌러도 달력이 안 열렸다. 마우스 기기에서는 앱이 직접 연다(`matchMedia('(pointer: fine)')`) → [[2026-10-23-날짜-칸-덮기와-클릭-이벤트-전파]] 5번

## 6. 하나 따라가 보기: 비행기 모드에서 앱 열기

1. (전날, 인터넷 됨) 아이콘으로 앱을 연다 → `index.html`이 `registerSW.js`를 부른다 → `navigator.serviceWorker.register('/sw.js')` → `sw.js`가 목록에 적힌 12개 파일을 받아 폰 캐시에 넣는다
2. (오늘, 비행기 모드) 아이콘을 누른다 → 브라우저가 `/`를 달라고 한다 → `sw.js`가 가로채 캐시의 `index.html`을 준다
3. `index.html`이 `assets/index-….js`를 달라고 한다 → 역시 캐시에서
4. JS가 돌면서 IndexedDB에서 기록을 읽는다 → 하우스 목록이 뜬다
5. 기록을 저장한다 → IndexedDB에 들어간다 (서버로 보내는 것은 6단계)

## 7. 이걸 바꾸려면 어디를 고치나

| 바꿀 것 | 고칠 곳 |
|---|---|
| 홈 화면 앱 이름 | `vite.config.ts`의 `manifest.name`, `short_name` (탭 제목은 `index.html`의 `<title>`) |
| 아이콘 | `public/icon.svg` → PNG 다시 만들기 |
| 상태 표시줄 색 | `vite.config.ts`의 `theme_color` + `index.html`의 `theme-color` (둘 다) |
| 새 버전을 바로 반영 (화면 새로 고침) | `virtual:pwa-register`로 등록하고 새로 고칠 때를 정하기. 입력 중 화면이 바뀌는 문제를 같이 풀어야 함 |
| 미리 받아 둘 파일 | `vite.config.ts`의 `includeAssets` (`public/` 안의 파일) |
