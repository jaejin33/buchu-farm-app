## 2. `data/db.ts`: 폰 안 저장소

```ts
export type StoredRecord = FarmRecord & { synced: 0 | 1 }

export const db = new Dexie('buchu-farm') as Dexie & {
  records: EntityTable<StoredRecord, 'id'>
}

db.version(1).stores({
  records: 'id, synced',
})
```

- **`buchu-farm`이라는 DB에 `records` 저장소 하나**를 만든다. 서버(Supabase)의 `records` 테이블과 이름을 맞췄다
- **저장하는 것은 기록 + `synced`(서버로 보냈는지)다.** `A & B`는 "A의 항목과 B의 항목을 모두 가진 타입"이다. Java로 치면 `FarmRecord`를 상속해 `synced` 필드를 하나 더한 클래스다
- **`synced`가 `true/false`가 아니라 `1/0`인 이유:** IndexedDB는 true/false로 찾는 색인을 만들 수 없다. 6단계에서 "아직 안 보낸 기록"을 `where('synced').equals(0)`으로 찾으려고 숫자로 뒀다 → [[2026-10-22-IndexedDB와-Dexie]] 3번
- `'id, synced'`: 맨 앞(`id`)이 기본 키, 나머지가 색인이다. `house_no`, `type` 같은 다른 항목은 **적지 않아도 같이 저장된다.** 여기 적는 건 "찾을 때 쓸 항목"뿐이다
- `as Dexie & { records: ... }`: `db.records`가 어떤 타입인지 TS에 알려 준다. 안 쓰면 `db.records`를 쓸 때 타입 에러가 난다
- **`version(1)`은 앞으로 고치지 않는다.** 색인을 바꾸려면 `version(2)`를 새로 추가한다. Flyway에서 `V1__init.sql`을 고치지 않고 `V2__...sql`을 추가하는 것과 같다

## 3. `data/newId.ts`: 기록 id 만들기

```ts
export function newId(): string {
  if (typeof crypto.randomUUID === 'function') return crypto.randomUUID()
  return randomUuidFallback()
}
```

**왜 대체 방법이 필요한가:** `crypto.randomUUID()`는 브라우저가 "안전한 주소"(`https://`, `localhost`)라고 볼 때만 있다. 폰으로 PC 개발 서버(`http://192.168.x.x:5173`)에 들어가면 이 함수가 아예 없어서, 그대로 부르면 저장할 때 에러가 난다.

방법은 두 가지였다 → [[결정기록]] "기록 id: http에서는 직접 UUID를 만든다"

| 방법 | 장점 | 단점 |
|---|---|---|
| 개발 서버를 https로 띄움 (`@vitejs/plugin-basic-ssl`) | 코드를 안 고침 | 폰에서 "안전하지 않은 인증서" 경고 화면을 매번 넘겨야 함. 아버지께 보여드릴 때 곤란 |
| **http에서도 되는 `crypto.getRandomValues()`로 직접 만듦 (선택)** | 경고 없음, 패키지 추가 없음 | 코드 10줄 |

```ts
export function randomUuidFallback(): string {
  const bytes = crypto.getRandomValues(new Uint8Array(16))  // 무작위 바이트 16개
  bytes[6] = (bytes[6] & 0x0f) | 0x40   // 버전 4 표시
  bytes[8] = (bytes[8] & 0x3f) | 0x80   // 변형(variant) 표시
  const hex = [...bytes].map((b) => b.toString(16).padStart(2, '0')).join('')
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`
}
```

- `crypto.getRandomValues`는 http에서도 있다. 무작위 숫자를 만드는 기능이라 위험하지 않기 때문이다
- UUID 형식에는 "몇 번째 칸은 4로 시작한다" 같은 규칙이 있다. 두 줄의 비트 연산(`&`, `|`)이 그 자리를 맞춘다. 비트 연산은 Java와 같다. 이걸 맞춰야 Supabase의 `uuid` 칸에 그대로 들어간다
- `b.toString(16).padStart(2, '0')`: 숫자를 16진수 두 글자로 (`10` → `"0a"`). Java의 `String.format("%02x", b)`
- 결과는 `"3f2a9c1e-7b4d-4e8a-9c2f-1a2b3c4d5e6f"` 같은 모양이다. Java라면 `UUID.randomUUID().toString()` 한 줄이다
- **배포 주소(Vercel, `https://`)에서는 항상 `crypto.randomUUID()`를 쓴다.** 대체 코드는 개발 중 폰 시험용이다
- `typeof crypto.randomUUID === 'function'`: 함수가 있는지 확인한다. 없는 함수를 부르면 에러가 나므로 먼저 본다

## 4. `data/recordRepository.ts`: 화면의 유일한 입구

```ts
export const LOCAL_USER_ID = '00000000-0000-0000-0000-000000000000'

export type NewRecord = DistributiveOmit<FarmRecord, 'id' | 'recorded_by' | 'recorded_at'>

export async function addRecord(input: NewRecord): Promise<FarmRecord> {
  const record: FarmRecord = { ...input, id: newId(), recorded_by: LOCAL_USER_ID, recorded_at: nowTimestamp() }
  await db.records.add({ ...record, synced: 0 })
  return record
}

export function getAllRecords(): Promise<FarmRecord[]> {
  return db.records.toArray()
}

export function useRecords(): FarmRecord[] | undefined {
  return useLiveQuery(getAllRecords)
}
```

- **`NewRecord`: 화면이 넘기는 새 기록.** 화면은 동·날짜·종류·내용만 정하고, id·입력한 사람·입력 시각은 여기서 채운다. 화면이 id 만드는 법이나 지금 시각을 몰라도 된다. `DistributiveOmit`은 [[2026-10-22-TypeScript-구별된-유니온]] 4번
- **`addRecord`는 항상 `synced: 0`(아직 안 보냄)으로 저장한다.** 6단계에서 서버로 보내면 1로 바꾼다
- **`useRecords()`: 기록이 추가되면 화면이 저절로 다시 그려진다.** Dexie의 `useLiveQuery`가 IndexedDB를 지켜보다가 바뀌면 다시 읽는다. 그래서 `RecordForm`이 저장하면 `HouseList`가 따로 "새로고침해 줘"라고 듣지 않아도 바로 "오늘 약"이 뜬다. 처음 읽는 동안은 `undefined`다
- **고치기·지우기 함수가 없다.** 일부러 안 만들었다. 기록은 추가만 하고, 잘못 입력하면 `cancel` 기록을 추가한다 (`CLAUDE.md` 데이터 규칙)
- **`LOCAL_USER_ID`: 입력한 사람이 지금은 모두 같은 임시 id다.** 로그인은 6단계라서다. 그 전에 입력한 기록은 시험용으로 본다 → [[결정기록]] "로그인 전 입력한 사람은 임시 id"
- `async`, `await`, `Promise` → [[2026-10-22-React-state와-이벤트]] 6번

Spring Data JPA로 치면 이렇다.

```java
public interface RecordRepository extends Repository<FarmRecordEntity, UUID> {
    FarmRecordEntity save(FarmRecordEntity r);   // addRecord. update·delete는 일부러 안 둠
    List<FarmRecordEntity> findAll();            // getAllRecords
}
// useRecords에 해당하는 것은 Spring에 없다. 서버는 DB가 바뀌어도 화면을 다시 그려 주지 않는다
```

## 5. `domain/`에 더한 것

### `recordQueries.ts`: 입력 화면용 값

```ts
export function pesticideNames(records: readonly FarmRecord[]): string[] {
  const names: { name: string; workDate: string; recordedAt: string }[] = []
  for (const r of activeRecords(records)) {
    const name = r.type === 'spray' ? r.pesticide?.trim() : undefined
    if (name) names.push({ name, workDate: r.work_date, recordedAt: r.recorded_at })
  }
  names.sort(/* 최근 순 */)
  return [...new Set(names.map((n) => n.name))]
}
```

**약 목록**은 따로 저장하지 않고, 취소되지 않은 약 기록의 이름을 모아 만든다 (`CLAUDE.md` 데이터 규칙).

- **최근에 친 약이 앞**이다. 자주 쓰는 약을 찾기 쉽게 했다. 날짜가 같으면 나중에 입력한 쪽이 앞이다
- `r.pesticide?.trim()`: `?.`는 **값이 null이면 거기서 멈추고 `undefined`를 돌려준다.** 약 이름이 `null`이면 `.trim()`을 부르지 않는다. Java로는 `Optional.ofNullable(p).map(String::trim).orElse(null)`
- `if (name)`: 빈 글자(`""`), `null`, `undefined`는 모두 거짓으로 친다. 그래서 이름을 안 적었거나 빈칸만 적은 기록은 건너뛴다. Java에는 이런 규칙이 없어서 `name != null && !name.isEmpty()`로 쓴다
- `[...new Set(...)]`: 중복을 빼면서 **처음 나온 순서를 지킨다** (2단계의 구역 목록과 같은 방법, [[2026-10-22-React-컴포넌트와-props]] 3번). 최근 순으로 줄 세운 뒤 거르니 같은 이름은 가장 최근 것 하나만 남는다
- `b.workDate.localeCompare(a.workDate)`: 글자 비교. 음수/0/양수를 돌려준다. Java의 `b.compareTo(a)`

```ts
export function latestHarvestAmount(records, harvestId): HarvestAmountRecord | null
```

**수확량**: 수확 완료 기록 하나에 붙은 수확량 중 가장 나중에 입력한 것. 입력 화면에서 "이미 적은 양: 3박스 5단"을 보여줄 때 쓴다. 수확 완료 기록이 취소됐으면 수확량도 무시한다 (`CLAUDE.md` 규칙). 4단계 이력 화면에서도 쓸 수 있다.

### `harvestCalc.ts`의 `lastHarvestRecord`

```ts
export function lastHarvestRecord(records, houseNo): HarvestRecord | null {
  return lastOf(records, (r): r is HarvestRecord => r.type === 'harvest' && r.house_no === houseNo)
}
```

원래 `getHouseStatus` 안에 있던 "그 동의 마지막 수확 완료 기록 찾기"를 꺼내 공개했다. **수확량은 이 기록에 붙인다.** `getHouseStatus`가 수확 후 일수를 세는 기록과 수확량이 붙는 기록이 같은 함수에서 나오므로 서로 어긋날 일이 없다. `lastOf`는 [[2026-10-22-1단계-코드-읽기]] 3-3번.

### `today.ts`의 `nowTimestamp`

```ts
export function nowTimestamp(now: Date = new Date()): string {
  return now.toISOString()   // "2026-10-22T12:34:56.789Z"
}
```

기록의 `recorded_at`(입력한 시각)이다. 한 줄짜리지만 이 파일에 둔 이유: **현재 시각을 읽는 곳을 `today.ts` 한 곳으로 모은다**는 규칙 때문이다 ([[2026-10-22-2단계-코드-읽기]] 4번). 끝의 `Z`는 UTC라는 뜻이다. 날짜(`work_date`)와 달리 시각은 UTC로 둬도 된다. 비교할 때 `Date.parse`로 숫자로 바꾸기 때문이다 ([[2026-10-22-1단계-코드-읽기]] 3-2번).

### `types.ts`

```ts
pesticide: string | null // 약 이름. 안 적어도 된다 (null)
```

약 이름을 안 적어도 되게 했다 → [[결정기록]] "약 이름은 안 적어도 된다". `string | null`은 "글자 또는 null"이다. Java의 `String`은 원래 null이 될 수 있지만, TS는 `| null`을 적어야만 null을 허락한다. 그래서 `r.pesticide.trim()`처럼 쓰면 "null일 수 있다"는 빌드 에러가 나고, 위처럼 `?.`로 써야 한다.

## 6. `App.tsx`: 화면 전환

화면이 둘(목록, 기록 입력)뿐이라 **라우터 라이브러리 없이** "지금 열린 동 번호" 하나로 정한다.

```tsx
const records = useRecords()
const [houseNo, setHouseNo] = useState(() => houseNoFromHistory(history.state))
...
if (records === undefined) return null

const house = HOUSES.find((h) => h.no === houseNo)

return (
  <>
    {house === undefined ? (
      <HouseList ... onSelectHouse={openHouse} />
    ) : (
      <RecordForm key={house.no} house={house} ... onSaved={handleSaved} onCancel={() => history.back()} />
    )}
    {message !== null && <p className="toast" role="status">{message}</p>}
  </>
)
```

- **`houseNo`가 `null`이면 목록, 숫자면 그 동의 기록 화면이다.** Spring으로 치면 `/houses`와 `/houses/{no}/records/new` 두 주소를 컨트롤러 하나가 `if`로 가르는 셈이다
- **동을 누를 때 `history.pushState`로 방문 기록을 하나 쌓는다.** 그래서 폰의 뒤로 가기 버튼을 누르면 앱이 꺼지지 않고 목록으로 돌아온다. "‹ 목록" 버튼과 저장 후 돌아가기도 모두 `history.back()`을 써서, 돌아가는 길을 하나(`popstate` 이벤트)로 모았다 → [[2026-10-22-브라우저-history와-뒤로-가기]]
- **목록으로 돌아오면 보던 스크롤 위치로 되돌린다.** 25동을 기록하고 왔는데 맨 위로 튀면 다시 내려가야 한다. 열 때 `scrollY`를 `useRef`에 적어 두고, 돌아오면 `useLayoutEffect`에서 그 자리로 보낸다 → [[2026-10-22-React-state와-이벤트]] 5번
- **저장 알림("3동 약 저장했어요")은 3초 뒤 사라진다.** `useEffect` + `setTimeout`. 다른 동을 바로 열면 알림이 저장 버튼을 가리지 않게 지운다
- `if (records === undefined) return null`: IndexedDB를 처음 읽는 아주 짧은 동안은 아무것도 안 그린다. 빈 배열로 그리면 그 순간 모든 동이 "수확 기록 없음"으로 깜빡이기 때문이다
- `key={house.no}`: 다른 동의 기록 화면으로 바뀌면 입력하던 내용을 버리고 처음부터 시작하게 한다 → [[2026-10-22-React-state와-이벤트]] 5번
- **새로고침해도 보던 화면이 남는다.** `history.state`에 동 번호를 넣어 뒀기 때문에, 처음 값을 거기서 읽는다

## 7. `pages/RecordForm.tsx`: 기록 입력 화면

### 화면 순서

```
‹ 목록
```

- **일수·박스·단을 숫자가 아니라 글자(`'35'`, `''`)로 둔다.** 입력 칸이 비었을 때(`''`)와 0을 구분하고, 지우고 다시 적는 도중의 값도 담기 위해서다. 저장할 때 `Number(...)`로 바꾼다
- 문법 → [[2026-10-22-React-state와-이벤트]] 1~3번

### `buildRecord`: 고른 내용 → 새 기록

```tsx
function buildRecord(): { record: NewRecord; label: string } | null {
  if (!dateOk) return null
  const base = { house_no: house.no, work_date: workDate, memo: null }

  switch (kind) {
    case 'spray': {
      const name = pesticide.trim()
      return { record: { ...base, type: 'spray', pesticide: name || null }, label: name ? `약(${name})` : '약' }
    }
    case 'top_dressing':
      return { record: { ...base, type: 'top_dressing' }, label: '웃거름' }
    ...
    case 'harvest':
      if (harvestStep === 'harvest' && cycle >= 1) {
        return { record: { ...base, type: 'harvest', cycle_days: cycle }, label: '수확 완료' }
      }
      ...
      return null
    ...
  }
}

const built = buildRecord()
...
<button type="submit" className="save" disabled={built === null || saving}>
```

- **"저장해도 되는지"와 "무엇을 저장할지"를 한 함수가 정한다.** 덜 골랐으면 `null`을 돌려주고, 그러면 저장 버튼이 꺼진다. 저장 가능 조건과 저장 내용을 따로 쓰면 둘이 어긋날 수 있어서 하나로 묶었다
- `label`은 저장 후 알림("3동 **약(가약)** 저장했어요")에 쓴다
- `switch`는 Java와 같다. `case 'spray': { ... }`처럼 중괄호를 친 건 그 안에서 `const name`을 만들기 위해서다 (Java도 같음)
- `name || null`: 앞이 빈 글자면 뒤(`null`)를 쓴다. "안 적었으면 null로 저장"
- `{ ...base, type: 'spray', ... }`: 공통 항목을 펼쳐 넣고 종류별 항목을 더한다 ([[2026-10-22-Vitest-테스트와-순수-함수]] 3번의 테스트 도우미와 같은 모양)
- 타입 검사도 된다. `type: 'harvest'`인데 `cycle_days`를 빠뜨리면 빌드 에러가 난다
- `buildRecord`는 컴포넌트 함수 **안에** 있다. 그래서 `kind`, `pesticide`, `house` 같은 값을 인자로 받지 않고 바로 쓴다. 이렇게 바깥 함수의 변수를 그대로 쓰는 함수를 **클로저**라고 한다. Java 람다가 바깥의 `final` 변수를 쓰는 것과 비슷하다

### 저장

```tsx
async function handleSubmit(e: FormEvent) {
  e.preventDefault()
  if (built === null || saving) return
  setSaving(true)
  setError(null)
  try {
    await addRecord(built.record)
    onSaved(`${house.no}동 ${built.label} 저장했어요`)
  } catch {
    setError('저장하지 못했어요. 다시 눌러 주세요.')
    setSaving(false)
  }
}
```

- `e.preventDefault()`: `<form>`은 원래 제출하면 페이지를 새로 불러온다 (서버로 보내는 HTML 기본 동작). 그걸 막고 직접 처리한다
- **저장하는 동안 버튼을 끈다(`saving`).** 장갑 낀 손으로 두 번 눌러 같은 기록이 두 개 생기지 않게 한다
- 저장이 끝나면 `onSaved`로 App에 알린다. **기록 화면은 목록으로 돌아가는 법을 모른다.** App이 정한다
- `<form>`으로 감쌌기 때문에 숫자 칸에서 폰 키보드의 "완료/이동" 키를 눌러도 저장된다

### 작은 도우미

```tsx
function Choice({ selected, onClick, children }: { ...; children: ReactNode }) {
  return (
    <button type="button" className="choice" aria-pressed={selected} onClick={onClick}>
      {children}
    </button>
  )
}

function digitsOnly(value: string, maxLength: number): string {
  return value.replace(/\D/g, '').slice(0, maxLength)
}
```

- **`Choice`: 고르는 버튼 하나.** 종류, 수확 단계, 약 이름, 문제 모두 같은 모양이다
  - `children`: `<Choice>약</Choice>`처럼 태그 사이에 넣은 내용이다. Thymeleaf 프래그먼트에 HTML 덩어리를 넘기는 것과 비슷하다
  - `aria-pressed`: "눌린 상태"를 화면 읽기 기능에 알리는 HTML 속성이다. CSS도 이 값으로 고른 버튼을 초록으로 칠한다(`.choice[aria-pressed='true']`). 그래서 모양을 위한 클래스를 따로 두지 않았다
  - `type="button"`: `<form>` 안의 버튼은 기본이 "제출"이라, 안 적으면 종류만 골라도 저장된다. 그래서 저장 버튼만 `type="submit"`이다
- **`digitsOnly`: 숫자 칸에서 숫자 아닌 글자를 지운다.** `/\D/g`는 정규식으로 "숫자가 아닌 모든 글자"다. Java의 `value.replaceAll("\\D", "")`
  - 숫자 칸은 `<input type="number">` 대신 `inputMode="numeric"`(글자 칸 + 숫자 키패드)을 썼다. `type="number"`는 `1e3` 같은 글자가 들어가고, PC에서는 마우스 휠에 값이 바뀌는 등 말썽이 많다. 우리는 0 이상의 정수만 필요해서 글자 칸에 숫자만 남기는 쪽이 단순하다

### 날짜

```tsx
<input id="work-date" className="text-input" type="date" value={workDate} max={today} onChange={...} />
```

- 기본은 오늘이다 (`CLAUDE.md` 원칙). 어제 일을 오늘 적을 수 있게 지난 날짜는 고를 수 있다
- `max={today}`로 앞날을 막고, 빈칸이거나 앞날이면 저장 버튼이 꺼진다
- 옆에 "오늘 / 어제 / N일 전"을 보여 준다. 날짜 숫자만 보면 오늘인지 바로 알기 어렵다
- `type="date"` 칸은 `"2026-10-22"` 형식 글자를 돌려준다. 우리 날짜 규칙과 같아서 바꿀 필요가 없다

### 버튼 기본 모양 지우기 (`HouseList.css`)

```css
.house-row {

  margin: 0 -0.4rem;
  padding: 0.8rem 0.4rem;
  border: 0;
  background: none;

  text-align: left;
  -webkit-tap-highlight-color: transparent;
```

- 브라우저는 버튼에 회색 바탕·테두리·가운데 정렬·작은 글씨를 기본으로 준다. 그걸 다 지워서 2단계 줄 모양 그대로 보이게 했다 (`font: inherit` = 바깥 글자 크기 그대로)
- `:active`: **누르고 있는 동안**만 적용된다. 살짝 회색이 되어 눌렸다는 걸 눈으로 알 수 있다
- `margin: 0 -0.4rem`과 `padding: 0 0.4rem`: 바깥으로 0.4rem 넓히고 안쪽으로 0.4rem 들여서, 글자 위치는 그대로 두고 회색 바탕만 양옆으로 넓힌다. 회색이 글자에 딱 붙지 않게 하려는 것이다
- 구분선은 `.house-rows li + li`로 옮겼다. `.house-row`가 이제 `<li>` 안의 버튼이라 "바로 앞 형제" 관계가 `<li>`끼리이기 때문이다

- `box-sizing: border-box` (`.text-input`): 너비 100%에 테두리·안쪽 여백까지 포함한다. 없으면 칸이 카드 밖으로 삐져나온다

- 가장 작은 글자는 `0.8rem`(16px)이다. 2단계에서 정한 기준을 지킨다 → [[결정기록]] "문제 표시는 아이콘에 글자를 붙인다"
- 새 색 `--line-strong`(`index.css`): 버튼·입력 칸 테두리. 흰 카드 위에서 보이도록 구분선(`--line`)보다 진하다

- 화면(`RecordForm`) 자체는 테스트가 없다. 대신 아래처럼 브라우저로 직접 눌러 봤다

### 브라우저로 확인한 것

폰 크기(390px) 크롬을 띄워 자동으로 눌러 봤다 (확인용 스크립트는 레포에 넣지 않았다).

- 약 저장 → 알림 "3동 약(가약) 저장했어요" → 목록에 "오늘 약"
- 다시 열면 "가약" 버튼이 나오고, 이름 없이도 저장 버튼이 켜짐
- 어제 날짜로 수확 완료(36일) → "11월 26일 (목)부터 수확 가능" → 목록에 "수확 후 1일"
- 수확량: 비었을 때 저장 꺼짐, 3박스 5단 저장 후 다시 열면 "이미 적은 양: 3박스 5단"
- 수확 시작 → 목록에 "오늘 시작" + "수확 중"
- 문제: 없을 때 "생김" 미리 선택, 생김 저장 후에는 "해결됨" 미리 선택
- 뒤로 가기로 목록 복귀, 25동에서 돌아왔을 때 스크롤 위치 그대로
- 새로고침해도 기록이 남음

처음 확인에서 두 가지를 고쳤다. 수확 버튼("수확 시작")이 한 줄에 셋이라 두 줄로 꺾여서 "시작 / 완료 / 수확량"으로 줄였다. 고른 뒤 나타나는 칸이 저장 버튼 뒤에 숨어서 자동 스크롤을 넣었다. **진짜 폰에서는 아직 확인하지 않았다.**

## 12. 이걸 바꾸려면 어디를 고치나

| 바꿀 것 | 고칠 곳 |
|---|---|
| 종류 버튼 글자·순서 | `RecordForm.tsx`의 `KIND_BUTTONS` |
| 수확 단계 버튼 글자 | `RecordForm.tsx`의 `HARVEST_STEP_BUTTONS` |
| 저장 알림 문구 | `RecordForm.tsx`의 `buildRecord`의 `label` + `handleSubmit`의 `onSaved(...)` |
| 저장 알림이 떠 있는 시간 (3초) | `App.tsx`의 `setTimeout(..., 3000)` |
| 문제 이름 ("배수 불량" 등) | `pages/labels.ts`의 `PROBLEM_TAG` (목록·입력 화면 둘 다 바뀜) |
| 약 이름을 꼭 적게 하기 | `RecordForm.tsx`의 `case 'spray'`에서 이름이 비면 `null` 돌려주기 + `types.ts`의 `pesticide` 타입 |
| 약 목록 순서 | `recordQueries.ts`의 `pesticideNames` 정렬 + 테스트 |
| 앞날도 고를 수 있게 | `RecordForm.tsx`의 `dateOk`와 `max={today}` |
| 버튼 크기 | `RecordForm.css`의 `.choice`, `.save`의 `min-height` |
| 입력한 사람 (로그인 붙이기) | `recordRepository.ts`의 `LOCAL_USER_ID` (6단계) |
| IndexedDB 색인 추가 | `db.ts`에 `db.version(2).stores(...)` 새로 추가 (`version(1)`은 그대로) |
