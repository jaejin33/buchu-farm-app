## 1. 파일 지도

새로 생긴 파일은 ★, 고친 파일은 ✎로 표시했다.

```
src/
├ App.tsx                ✎ 화면이 셋이 되어 "지금 화면" 값으로 전환
├ App.css                ✎ 알림이 아래 버튼을 가리지 않게
├ index.css              ✎ 기록 입력·이력 화면이 같이 쓰는 머리(‹ 버튼, 제목)
├ domain/
│  ├ recordQueries.ts    ✎ houseHistory (그 동의 이력) 추가
│  └ harvestCalc.ts      ✎ isLater 공개 (이력 정렬에 씀)
└ pages/
   ├ labels.ts           ✎ relativeDay ("오늘", "어제", "3일 전") 추가
   ├ RecordForm.tsx/.css ✎ 위쪽에 "지난 기록 ›" 버튼, 머리 CSS는 index.css로
   └ History.tsx/.css    ★ 이력 화면
```

누가 누구를 부르는지 (이력 화면 쪽만):

```
App.tsx
  ├→ pages/RecordForm.tsx    "지난 기록 ›"을 누르면 onOpenHistory()
  └→ pages/History.tsx
        ├→ domain/recordQueries.ts   houseHistory, latestHarvestAmount
        │     └→ domain/harvestCalc.ts   activeRecords, isLater
        ├→ data/recordRepository.ts  addRecord (취소 기록 추가)
        └→ pages/labels.ts           formatDate, relativeDay, PROBLEM_TAG
```

계층 규칙은 3단계와 같다. 이력 화면도 `recordRepository`만 부르고, "무엇을 보여줄지"는 `domain/`의 순수 함수(`houseHistory`)가 정한다.

**들어가는 길:** 목록 → 동 누르기(기록 입력) → 오른쪽 위 **"지난 기록 ›"** → 이력. 목록에서 동을 누르면 예전처럼 바로 입력 화면이 열린다. 기록 입력이 주된 일이라 30초 원칙을 지키려고 이력은 한 단계 안쪽에 두었다 → [[결정기록]] "이력 화면 구성"

## 2. `domain/recordQueries.ts`의 `houseHistory`: 무엇을 보여줄지

```ts
export function houseHistory(records: readonly FarmRecord[], houseNo: number): FarmRecord[] {
  return activeRecords(records)
    .filter((r) => r.house_no === houseNo)
    .filter((r) => r.type !== 'harvest_amount' || latestHarvestAmount(records, r.target_id)?.id === r.id)
    .sort((a, b) => (isLater(a, b) ? -1 : isLater(b, a) ? 1 : 0))
}
```

위에서 아래로 한 줄씩 거른다. Java Stream의 `.filter(...).filter(...).sorted(...)`와 같다.

1. `activeRecords(records)`: **취소된 기록과 취소 기록 자체를 뺀다.** `CLAUDE.md`: "화면에서는 취소된 기록을 숨긴다"
2. 그 동의 기록만
3. **수확량은 수확마다 하나만 남긴다.** 수확량이 아니면 통과. 수확량이면 "그 수확의 최신 수확량(`latestHarvestAmount`)이 바로 나인가"를 본다
   - 3박스로 적었다가 4박스로 다시 적으면 둘 다 살아 있는 기록이다. 하지만 계산에 쓰는 것은 나중 것(4박스)뿐이라, 둘 다 보이면 헷갈린다
   - 4박스를 취소하면 3박스가 다시 "최신"이 되어 보인다
   - 수확 완료 기록이 취소됐으면 `latestHarvestAmount`가 `null`을 돌려주므로 그 수확량도 빠진다
   - `?.id`: 결과가 `null`이면 `.id`를 읽지 않고 `undefined`가 된다 → `r.id`와 같지 않음 → 빠짐 ([[2026-10-22-3단계-코드-읽기]] 5번)
   - `A || B`: A가 참이면 B는 보지 않는다 (Java의 `||`와 같음)
4. **최근 기록이 앞.** 1단계에서 만든 `isLater`(작업 날짜가 늦은 쪽, 같은 날이면 나중에 입력한 쪽)를 그대로 쓴다. "마지막 기록"을 고르는 기준과 이력 순서가 같아야 화면이 계산과 어긋나지 않는다

정렬 비교 함수는 "a가 앞이면 음수, b가 앞이면 양수, 같으면 0"이다 ([[2026-10-22-React-컴포넌트와-props]] 3번). Java로 쓰면 이렇다.

```java
Comparator<FarmRecord> latestFirst = (a, b) -> isLater(a, b) ? -1 : isLater(b, a) ? 1 : 0;
```

`isLater`를 공개(`export`)하려고 `harvestCalc.ts`에서 앞에 `export`만 붙였다. 1단계에는 이 파일 안에서만 쓰던 함수다.

## 3. `pages/History.tsx`: 이력 화면

### 한 줄의 글자: `describe`

```tsx
function describe(r: FarmRecord, records: readonly FarmRecord[]): { title: string; detail: string | null; note?: string } {
  switch (r.type) {
    case 'spray':
      return { title: '약', detail: r.pesticide }
    case 'harvest':
      return { title: '수확 완료', detail: `수확 가능까지 ${r.cycle_days}일` }
    case 'harvest_amount': {
      const target = records.find((t) => t.id === r.target_id)
      return {
        title: '수확량',
        detail: `${r.boxes}박스 ${r.bunches}단`,
        note: target === undefined ? undefined : `${formatDate(target.work_date)} 수확분`,
      }
    }
    ...
  }
}
```

기록 한 개를 `약 가약`, `수확량 4박스 5단 / 10월 20일 (화) 수확분` 같은 글자로 바꾼다.

- **`switch`가 여덟 종류를 다 다룬다.** 함수 끝에 `return`이 없는데도 에러가 안 나는 건, TS가 "`type`이 될 수 있는 값을 모두 `case`로 다뤘다"는 것을 알기 때문이다. 나중에 기록 종류를 하나 추가하고 여기를 빠뜨리면 "값을 돌려주지 않을 수 있다"는 빌드 에러가 난다. Java 21의 `sealed` + `switch` 식에서 빠진 `case`가 컴파일 에러인 것과 같다 ([[2026-10-22-TypeScript-구별된-유니온]] 5번)
- `case 'spray'` 안에서는 `r.pesticide`를, `case 'harvest'` 안에서는 `r.cycle_days`를 바로 쓴다. `switch (r.type)`도 `if (r.type === ...)`처럼 타입을 좁혀 준다
- 약 이름이 없으면(`null`) `detail`도 `null`이라 "약"만 보인다
- `note?: string`: `?`가 붙은 항목은 **없어도 되는 항목**이다. 수확량만 아랫줄 설명(어느 수확의 양인지)을 가진다. 수확량은 완료 다음 날 입력하므로 날짜 카드와 수확한 날이 다르기 때문이다
- 취소 기록(`case 'cancel'`)도 다루지만 이력에는 나오지 않는다 (`houseHistory`가 뺌). 모든 종류를 다뤄야 위의 빌드 검사가 되므로 적어 두었다

### 날짜별로 묶기: `groupByDate`

```tsx
function groupByDate(records: FarmRecord[]): { date: string; records: FarmRecord[] }[] {
  const groups: { date: string; records: FarmRecord[] }[] = []
  for (const r of records) {
    const last = groups.at(-1)
    if (last !== undefined && last.date === r.work_date) last.records.push(r)
    else groups.push({ date: r.work_date, records: [r] })
  }
  return groups
}
```

- 이미 최근 순으로 줄 서 있으니, **앞 기록과 날짜가 같으면 같은 묶음에, 다르면 새 묶음**을 만든다
- `groups.at(-1)`: 배열의 **마지막** 항목. 음수는 뒤에서부터 센다. 빈 배열이면 `undefined`. Java 21의 `list.getLast()`와 비슷하다 (Java는 빈 리스트면 예외)
- 결과: `[{ date: '2026-10-22', records: [문제, 약, 수확량] }, { date: '2026-10-21', records: [웃거름] }, ...]`
- Java Stream의 `groupingBy`를 쓰지 않은 이유: 순서를 지키면서 이어진 것끼리만 묶는 게 이 반복문이 더 단순하다

### 취소: 한 번 더 묻는다

```tsx
const [confirmingId, setConfirmingId] = useState<string | null>(null)
...
{!confirming && <button className="history-cancel" onClick={() => { setConfirmingId(r.id); setError(null) }}>취소</button>}
{confirming && (
  <div className="history-confirm">
    <p>이 기록을 취소할까요?{hasAmount && <> 이 수확의 수확량도 함께 빠져요.</>}</p>
    <button className="confirm-no" onClick={() => setConfirmingId(null)}>아니요</button>
    <button className="confirm-yes" disabled={busy} onClick={() => cancelRecord(r)}>네, 취소</button>
  </div>
)}
```

- **[취소]를 누르면 바로 취소하지 않고, 그 줄에서 "이 기록을 취소할까요?"를 묻는다.** 장갑 낀 손으로 옆 줄을 잘못 눌러도 바로 취소되지 않게 했다 → [[결정기록]] "잘못 입력한 기록은 이력 화면에서 취소"
- **묻는 중인 기록 id 하나(`confirmingId`)만 기억한다.** 다른 줄의 [취소]를 누르면 그 줄로 옮겨 간다. 한 번에 한 줄만 묻는다
- 브라우저 기본 확인 창(`window.confirm("...")`)을 쓰지 않은 이유: 글씨가 작고 폰마다 모양이 다르며, 어느 줄을 취소하는지 화면에서 보이지 않는다. 그 줄을 옅은 주황으로 칠해 두고 바로 아래에서 묻는 게 아버지께 덜 헷갈린다
- **수확 완료를 취소할 때는 "이 수확의 수확량도 함께 빠져요"를 붙인다.** `hasAmount = r.type === 'harvest' && latestHarvestAmount(records, r.id) !== null`. 미리 알려 주지 않으면 수확량이 왜 사라졌는지 모른다
- `<> 이 수확의 수확량도 함께 빠져요.</>`: 태그 없이 글자만 넣는 프래그먼트 ([[2026-10-22-2단계-코드-읽기]] 8번 `Elapsed`)
- **[네, 취소]는 진한 주황**, 저장 버튼(초록)과 다른 색이다. 되돌리기 어려운 쪽이라는 표시다

### 취소 기록 추가

```tsx
async function cancelRecord(r: FarmRecord) {
  if (busy) return
  setBusy(true)
  setError(null)
  try {
    await addRecord({ type: 'cancel', house_no: house.no, work_date: today, target_id: r.id, memo: null })
    setConfirmingId(null)
    onCanceled(`${describe(r, records).title} 기록을 취소했어요`)
  } catch {
    setError('취소하지 못했어요. 다시 눌러 주세요.')
  } finally {
    setBusy(false)
  }
}
```

- **지우지 않고 `cancel` 기록을 하나 추가한다.** 저장은 기록 입력과 같은 `addRecord`다. 저장소에 "취소" 전용 함수를 따로 만들지 않았다. 취소도 기록 추가일 뿐이다 → [[2026-10-22-추가만-하는-기록과-취소]]
- **취소 기록의 날짜(`work_date`)는 오늘(취소한 날)이다.** 취소한 기록의 날짜가 아니다. 계산은 취소 기록의 날짜를 쓰지 않아서 결과는 같고, 나중에 "언제 취소했나"를 볼 수 있다
- `busy`: 저장하는 동안 두 번 눌러 취소 기록이 두 개 생기지 않게 막는다 (두 개 생겨도 계산은 같지만 기록이 지저분해진다)
- `finally`: 성공하든 실패하든 마지막에 실행한다. Java의 `try { } catch { } finally { }`와 같다. 3단계 저장(`handleSubmit`)은 성공하면 화면을 떠나서 `finally`가 필요 없었고, 이력 화면은 취소 뒤에도 남아 있으므로 `busy`를 풀어야 한다
- 취소하면 **그 줄이 저절로 사라진다.** `useLiveQuery`가 IndexedDB가 바뀐 걸 보고 기록을 다시 읽고, `houseHistory`가 취소된 기록을 빼기 때문이다. 화면에서 그 줄을 직접 지우는 코드는 없다 ([[2026-10-22-IndexedDB와-Dexie]] 4번)
- 알림("약 기록을 취소했어요")은 App이 띄운다 (`onCanceled`)

### 묻는 줄로 스크롤

```tsx
const confirmRef = useRef<HTMLLIElement>(null)

useEffect(() => {
  confirmRef.current?.scrollIntoView({ block: 'nearest', behavior: 'smooth' })
}, [confirmingId])
...
<li ref={confirming ? confirmRef : undefined}>
```

화면 아래쪽 줄의 [취소]를 누르면 [네, 취소] 버튼이 화면 밖에 생겼다(브라우저로 확인함). 그래서 묻는 줄이 바뀔 때마다 그 줄이 다 보이도록 스크롤한다. 3단계 기록 화면의 `detailRef`와 같은 방법이다.

- `ref={confirming ? confirmRef : undefined}`: **묻는 중인 줄에만** `ref`를 붙인다. 그래서 `confirmRef.current`는 항상 그 줄이다. 묻는 줄이 없으면 `null`이라 `?.`로 아무것도 안 한다
- `HTMLLIElement`: `<li>` 태그의 타입이다. `<section>`은 `HTMLElement`로 썼다 (3단계)

## 4. `App.tsx`: 화면이 셋

### "지금 화면" 값

```tsx
type Screen = { houseNo: number; view: 'form' | 'history' } | null

function screenFromHistory(state: unknown): Screen {
  const s = state as { houseNo?: unknown; view?: unknown } | null
  if (typeof s?.houseNo !== 'number') return null
  return { houseNo: s.houseNo, view: s.view === 'history' ? 'history' : 'form' }
}
```

- 3단계에는 화면이 둘이라 "열린 동 번호"(`houseNo`) 하나로 충분했다. 이력이 생기면서 **어느 동의, 어느 화면인지** 둘 다 필요해졌다
- `null` = 목록, `{ houseNo: 3, view: 'form' }` = 3동 기록 입력, `{ houseNo: 3, view: 'history' }` = 3동 이력
- `'form' | 'history'`: 두 글자 중 하나만 되는 리터럴 타입 ([[2026-10-22-TypeScript-구별된-유니온]] 1-(3))
- Java로 치면 이렇다

  ```java
  enum View { FORM, HISTORY }
  record Screen(int houseNo, View view) {}
  Screen screen = null;   // null이면 목록
  ```

- 방문 기록에 넣었던 값을 꺼낼 때(`screenFromHistory`)는 모양을 확인하고 꺼낸다 ([[2026-10-22-브라우저-history와-뒤로-가기]] 3번)

### 화면 열기: `open`

```tsx
function open(next: NonNullable<Screen>) {
  if (screen === null) listScrollY.current = window.scrollY
  setMessage(null)
  history.pushState(next, '')
  setScreen(next)
}
...
<HouseList onSelectHouse={(no) => open({ houseNo: no, view: 'form' })} ... />
<RecordForm onOpenHistory={() => open({ houseNo: house.no, view: 'history' })} ... />
```

- 3단계의 `openHouse(no)`를 **어느 화면이든 여는 함수 하나**로 바꿨다
- `NonNullable<Screen>`: `Screen`에서 `null`을 뺀 타입. "열 화면"은 목록(`null`)일 수 없어서다. 목록으로는 항상 `history.back()`으로 돌아간다
- 스크롤 위치는 **목록에서 떠날 때만** 적어 둔다. 기록 화면에서 이력으로 갈 때 적으면 목록 위치를 덮어써 버린다

### 스크롤: 객체 대신 글자로 비교

```tsx
const screenKey = screen === null ? 'list' : `${screen.view}-${screen.houseNo}`
useLayoutEffect(() => {
  window.scrollTo(0, screenKey === 'list' ? listScrollY.current : 0)
}, [screenKey])
```

`useLayoutEffect`의 둘째 인자 `[...]`는 "이 값이 바뀌면 다시 실행"이다. React는 바뀌었는지를 **`===`로 비교**한다. 객체는 내용이 같아도 새로 만들면 다른 것으로 본다.

```java
// Java로 치면
new Screen(3, FORM) == new Screen(3, FORM)       // false (주소 비교)
new Screen(3, FORM).equals(new Screen(3, FORM))  // true  (내용 비교)
```

JS의 `===`는 객체에 대해 Java의 `==`(주소 비교)와 같다. 그래서 `screen` 객체를 그대로 넣으면 같은 화면이어도 다시 실행될 수 있다. `'form-3'`, `'history-3'`, `'list'` 같은 **글자**로 바꾸면 글자는 내용으로 비교되므로 화면이 정말 바뀔 때만 실행된다.

### 세 화면 중 하나 그리기

```tsx
{screen === null || house === undefined ? (
  <HouseList ... />
) : screen.view === 'form' ? (
  <RecordForm ... />
) : (
  <History house={house} records={records} today={today} onBack={() => history.back()} onCanceled={setMessage} />
)}
```

- 삼항 연산자를 이어 쓴 세 갈래다 (`if / else if / else`)
- `onCanceled={setMessage}`: `(message) => setMessage(message)`처럼 감쌀 필요 없이 `set` 함수를 그대로 넘겼다. 받는 쪽이 글자 하나를 넘기면 그게 알림이 된다

### 알림이 버튼을 가리지 않게 (`App.css`)

```css
.toast { pointer-events: none; }
```

이력 화면에서는 취소 뒤에도 화면에 남으므로, 아래에 뜬 알림 밑에 [취소] 버튼이 있을 수 있다. `pointer-events: none`이면 알림은 눌리지 않고 **누른 것이 아래 버튼으로 간다.** 알림은 보기만 하는 것이라 눌릴 필요가 없다.

## 5. `RecordForm.tsx`와 같이 쓰는 머리

```tsx
<div className="top-bar">
  <button type="button" className="text-button" onClick={onCancel}>‹ 목록</button>
  <button type="button" className="text-button" onClick={onOpenHistory}>지난 기록 ›</button>
</div>
<header className="page-header">
  <p>{house.zone}</p>
  <h1>{house.no}동 기록</h1>
</header>
```

- 기록 화면 오른쪽 위에 **"지난 기록 ›"**를 넣었다. 누르면 `onOpenHistory()` → App이 이력 화면을 연다. 기록 화면은 이력 화면을 모른다
- 이력 화면 왼쪽 위는 **"‹ 3동 기록"**이다. 어디로 돌아가는지 글자로 보여 준다
- 두 화면의 머리 모양이 같아서 CSS(`.top-bar`, `.text-button`, `.page-header`)를 `RecordForm.css`에서 `index.css`로 옮겼다. 3단계의 `.back`, `.record-form-header`, `.zone-name`은 이 이름들로 바뀌었다. 한 화면 전용 CSS 파일에 두면 다른 화면이 그 파일을 import해야 해서 헷갈린다
- `.top-bar`: `display: flex; justify-content: space-between` → 첫 버튼은 왼쪽 끝, 둘째 버튼은 오른쪽 끝
- 날짜 옆 "오늘 / 어제 / N일 전"은 `labels.ts`의 `relativeDay`로 옮겼다. 이력 화면의 날짜 카드도 같은 글자를 쓴다

## 6. `History.css`에서 볼 것

- **날짜마다 둥근 흰 카드**: 목록 화면의 구역 카드와 같은 모양이다
- 줄은 `display: flex; justify-content: space-between`으로 [글자 ... 취소 버튼]. 버튼은 `flex-shrink: 0`으로 줄어들지 않게 한다
- **아랫줄 설명** `.history-note { flex-basis: 100%; }`: 글자 묶음이 `flex-wrap: wrap`이라, 너비 100%를 차지하는 항목은 자기 줄로 내려간다. 처음에는 "4박스 5단 · 10월 20일 (화) 수확분"을 한 글자로 붙였더니 폰 폭에서 "수확 / 분"으로 꺾였다(브라우저로 확인함). 그래서 따로 한 줄로 뺐다
- **묻는 줄**은 옅은 주황 바탕(`--warn-weak`)이다. `margin: 0 -0.5rem; padding: ... 0.5rem`으로 글자 위치는 그대로 두고 바탕만 양옆으로 넓혔다 (목록 줄의 눌림 효과와 같은 방법, [[2026-10-22-3단계-코드-읽기]] 9번)
- [취소] 버튼은 회색 테두리로 **덜 눈에 띄게** 했다. 줄마다 있어서 진하면 화면이 시끄럽다. 그래도 높이는 2.6rem(52px)으로 누르기 쉽게 했다
- 가장 작은 글자는 `0.85rem`(17px). 16px 기준을 지킨다

## 7. 하나 따라가 보기: 3동의 "약 가약"을 취소

3동에 이런 기록이 있다고 하자 (오늘 10월 22일).

| 기록 | 종류 | 날짜 | 내용 |
|---|---|---|---|
| h | 수확 완료 | 10-20 | 35일 |
| a1 | 수확량 | 10-22 | h에 3박스 0단 (07시 입력) |
| a2 | 수확량 | 10-22 | h에 4박스 5단 (09시 입력) |
| t | 웃거름 | 10-21 | |
| s | 약 | 10-22 | 가약 (10시 입력) |
| p | 문제 | 10-22 | 💧 배수 불량 생김 (11시 입력) |

1. 3동 기록 화면에서 **"지난 기록 ›"** → `open({ houseNo: 3, view: 'history' })` → 방문 기록 `[목록] → [3동 기록] → [3동 이력]`
2. `houseHistory(records, 3)`
   - 취소된 것 없음 → 여섯 개 모두 살아 있음
   - 수확량 a1은 h의 최신 수확량(a2)이 아니므로 빠짐
   - 최근 순: p(11시), s(10시), a2(09시) (모두 10-22라 나중에 입력한 것이 앞) → t (10-21) → h (10-20)
3. `groupByDate` → 카드 세 장

   ```
   10월 22일 (목) 오늘
     💧 배수 불량  생김                 [취소]
     약  가약                           [취소]
     수확량  4박스 5단                  [취소]
     10월 20일 (화) 수확분
   10월 21일 (수) 어제
     웃거름                             [취소]
   10월 20일 (화) 2일 전
     수확 완료  수확 가능까지 35일       [취소]
   ```

4. "약 가약" 줄의 **[취소]** → `confirmingId = 's'` → 그 줄이 주황으로 바뀌고 "이 기록을 취소할까요?" [아니요] [네, 취소]
5. **[네, 취소]** → `cancelRecord(s)` → `addRecord({ type: 'cancel', house_no: 3, work_date: '2026-10-22', target_id: 's', memo: null })` → IndexedDB에 취소 기록 c 추가
6. `useLiveQuery`가 다시 읽음 → `activeRecords`가 s와 c를 뺌 → 약 줄이 사라짐. 알림 "약 기록을 취소했어요"
7. 뒤로 가기 두 번 → 목록. 3동 줄에서 "오늘 약"이 없어졌다 (`getHouseStatus`도 `activeRecords`를 거치므로)

이어서 a2(4박스)를 취소하면 a1(3박스 0단)이 h의 최신 수확량이 되어 다시 보인다. h(수확 완료)를 취소하려고 하면 "이 수확의 수확량도 함께 빠져요"가 함께 나온다.

## 8. 테스트 (76개)

3단계 70개에 `houseHistory` 테스트 6개를 더했다 (`recordQueries.test.ts`, 이제 17개).

| 테스트 | 지키는 규칙 |
|---|---|
| 그 동의 기록만, 작업 날짜가 늦은 순으로 | 이력 순서 |
| 같은 날이면 나중에 입력한 기록이 앞 | "마지막" 기준과 같은 순서 |
| 취소된 기록과 cancel 기록은 보이지 않는다 | `CLAUDE.md`: 화면에서는 취소된 기록을 숨긴다 |
| 수확량은 수확마다 가장 나중에 입력한 것 하나만 보인다 | 계산에 쓰는 수확량만 |
| 나중 수확량을 취소하면 그 전 수확량이 다시 보인다 | 수확량 취소 |
| 수확 완료 기록을 취소하면 그 수확량도 보이지 않는다 | `CLAUDE.md`: 수확 기록이 취소되면 그 수확량도 무시 |

화면(`History.tsx`) 자체는 테스트가 없다. 대신 폰 크기(390px) 크롬으로 눌러 봤다 (확인용 스크립트는 레포에 넣지 않았다).

- 이력이 날짜별 카드로, 최근 순으로 나옴. 수확량은 최신 것 하나와 "수확분" 줄
- 수확 완료 [취소] → "수확량도 함께 빠져요" 문구 → [아니요]로 닫힘
- 약 [취소] → [네, 취소] → 줄이 사라지고 알림, 목록에서 "오늘 약"이 없어짐
- 4박스 수확량 취소 → 3박스 수확량이 다시 보임
- 이력에서 새로고침해도 이력 화면 그대로
- 폰 뒤로 가기: 이력 → 기록 입력 → 목록. "‹ 3동 기록" 버튼도 기록 화면으로
- 기록 없는 동: "아직 기록이 없어요"

처음 확인에서 두 가지를 고쳤다. 수확량의 "수확분"이 중간에서 꺾여 따로 한 줄로 뺐고, 아래쪽 줄을 취소하려 하면 [네, 취소]가 화면 밖에 있어서 자동 스크롤을 넣었다. 알림 문구도 날짜를 넣었더니 두 줄로 꺾여서 "약 기록을 취소했어요"로 줄였다. **진짜 폰에서는 아직 확인하지 않았다.**
