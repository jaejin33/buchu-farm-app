## 2. `data/db.ts`: 폰 안 저장소

```ts
export type StoredRecord = FarmRecord & { synced: 0 | 1 }

export const db = new Dexie('buchu-farm') as Dexie & {
  records: EntityTable<StoredRecord, 'id'>
}

db.version(1).stores({
  records: 'id, synced',
})
```

- **`buchu-farm`이라는 DB에 `records` 저장소 하나**를 만든다. 서버(Supabase)의 `records` 테이블과 이름을 맞췄다
- **저장하는 것은 기록 + `synced`(서버로 보냈는지)다.** `A & B`는 "A의 항목과 B의 항목을 모두 가진 타입"이다. Java로 치면 `FarmRecord`를 상속해 `synced` 필드를 하나 더한 클래스다
- **`synced`가 `true/false`가 아니라 `1/0`인 이유:** IndexedDB는 true/false로 찾는 색인을 만들 수 없다. 6단계에서 "아직 안 보낸 기록"을 `where('synced').equals(0)`으로 찾으려고 숫자로 뒀다 → [[2026-10-22-IndexedDB와-Dexie]] 3번
- `'id, synced'`: 맨 앞(`id`)이 기본 키, 나머지가 색인이다. `house_no`, `type` 같은 다른 항목은 **적지 않아도 같이 저장된다.** 여기 적는 건 "찾을 때 쓸 항목"뿐이다
- `as Dexie & { records: ... }`: `db.records`가 어떤 타입인지 TS에 알려 준다. 안 쓰면 `db.records`를 쓸 때 타입 에러가 난다
- **`version(1)`은 앞으로 고치지 않는다.** 색인을 바꾸려면 `version(2)`를 새로 추가한다. Flyway에서 `V1__init.sql`을 고치지 않고 `V2__...sql`을 추가하는 것과 같다

## 3. `data/newId.ts`: 기록 id 만들기

```ts
export function newId(): string {
  if (typeof crypto.randomUUID === 'function') return crypto.randomUUID()
  return randomUuidFallback()
}
```

**왜 대체 방법이 필요한가:** `crypto.randomUUID()`는 브라우저가 "안전한 주소"(`https://`, `localhost`)라고 볼 때만 있다. 폰으로 PC 개발 서버(`http://192.168.x.x:5173`)에 들어가면 이 함수가 아예 없어서, 그대로 부르면 저장할 때 에러가 난다.

방법은 두 가지였다 → [[결정기록]] "기록 id: http에서는 직접 UUID를 만든다"

| 방법 | 장점 | 단점 |
|---|---|---|
| 개발 서버를 https로 띄움 (`@vitejs/plugin-basic-ssl`) | 코드를 안 고침 | 폰에서 "안전하지 않은 인증서" 경고 화면을 매번 넘겨야 함. 아버지께 보여드릴 때 곤란 |
| **http에서도 되는 `crypto.getRandomValues()`로 직접 만듦 (선택)** | 경고 없음, 패키지 추가 없음 | 코드 10줄 |

```ts
export function randomUuidFallback(): string {
  const bytes = crypto.getRandomValues(new Uint8Array(16))  // 무작위 바이트 16개
  bytes[6] = (bytes[6] & 0x0f) | 0x40   // 버전 4 표시
  bytes[8] = (bytes[8] & 0x3f) | 0x80   // 변형(variant) 표시
  const hex = [...bytes].map((b) => b.toString(16).padStart(2, '0')).join('')
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`
}
```

- `crypto.getRandomValues`는 http에서도 있다. 무작위 숫자를 만드는 기능이라 위험하지 않기 때문이다
- UUID 형식에는 "몇 번째 칸은 4로 시작한다" 같은 규칙이 있다. 두 줄의 비트 연산(`&`, `|`)이 그 자리를 맞춘다. 비트 연산은 Java와 같다. 이걸 맞춰야 Supabase의 `uuid` 칸에 그대로 들어간다
- `b.toString(16).padStart(2, '0')`: 숫자를 16진수 두 글자로 (`10` → `"0a"`). Java의 `String.format("%02x", b)`
- 결과는 `"3f2a9c1e-7b4d-4e8a-9c2f-1a2b3c4d5e6f"` 같은 모양이다. Java라면 `UUID.randomUUID().toString()` 한 줄이다
- **배포 주소(Vercel, `https://`)에서는 항상 `crypto.randomUUID()`를 쓴다.** 대체 코드는 개발 중 폰 시험용이다
- `typeof crypto.randomUUID === 'function'`: 함수가 있는지 확인한다. 없는 함수를 부르면 에러가 나므로 먼저 본다

## 4. `data/recordRepository.ts`: 화면의 유일한 입구

```ts
export type NewRecord = DistributiveOmit<FarmRecord, 'id' | 'recorded_by' | 'recorded_at'>

export async function addRecord(input: NewRecord): Promise<FarmRecord> {
  const user = getCurrentUser()
  if (user === null) throw new Error('로그인 전에는 기록할 수 없어요')
  const record: FarmRecord = { ...input, id: newId(), recorded_by: user.id, recorded_at: nowTimestamp() }
  await db.records.add({ ...record, synced: 0 })
  return record
}

export function getAllRecords(): Promise<FarmRecord[]> {
  return db.records.toArray()
}

export function useRecords(): FarmRecord[] | undefined {
  return useLiveQuery(getAllRecords)
}
```

- **`NewRecord`: 화면이 넘기는 새 기록.** 화면은 동·날짜·종류·내용만 정하고, id·입력한 사람·입력 시각은 여기서 채운다. 화면이 id 만드는 법이나 지금 시각을 몰라도 된다. `DistributiveOmit`은 [[2026-10-22-TypeScript-구별된-유니온]] 4번
- **`addRecord`는 항상 `synced: 0`(아직 안 보냄)으로 저장한다.** 6단계에서 서버로 보내면 1로 바꾼다
- **`useRecords()`: 기록이 추가되면 화면이 저절로 다시 그려진다.** Dexie의 `useLiveQuery`가 IndexedDB를 지켜보다가 바뀌면 다시 읽는다. 그래서 `RecordForm`이 저장하면 `HouseList`가 따로 "새로고침해 줘"라고 듣지 않아도 바로 "오늘 약"이 뜬다. 처음 읽는 동안은 `undefined`다
- **고치기·지우기 함수가 없다.** 일부러 안 만들었다. 기록은 추가만 하고, 잘못 입력하면 `cancel` 기록을 추가한다 (`CLAUDE.md` 데이터 규칙)
- **입력한 사람(`recorded_by`)은 이 폰에서 로그인한 사람이다** (`getCurrentUser()`, 6단계). 3단계 때는 로그인이 없어서 모두 임시 id(`LOCAL_USER_ID`)였고, 그 시험 기록은 로그인할 때 지운다 → [[2026-10-23-6단계-코드-읽기]] 5번
- `async`, `await`, `Promise` → [[2026-10-22-React-state와-이벤트]] 6번

Spring Data JPA로 치면 이렇다.

```java
public interface RecordRepository extends Repository<FarmRecordEntity, UUID> {
    FarmRecordEntity save(FarmRecordEntity r);   // addRecord. update·delete는 일부러 안 둠
    List<FarmRecordEntity> findAll();            // getAllRecords
}
// useRecords에 해당하는 것은 Spring에 없다. 서버는 DB가 바뀌어도 화면을 다시 그려 주지 않는다
```

## 5. `domain/`에 더한 것

### `recordQueries.ts`: 입력 화면용 값

```ts
// 3단계에 만든 모양. 7단계에서 몸통을 recentNames로 옮기고, 이름 뽑기만 함수로 넘기게 바꿨다 (13번)
export function pesticideNames(records: readonly FarmRecord[]): string[] {
  const names: { name: string; workDate: string; recordedAt: string }[] = []
  for (const r of activeRecords(records)) {
    const name = r.type === 'spray' ? r.pesticide?.trim() : undefined
    if (name) names.push({ name, workDate: r.work_date, recordedAt: r.recorded_at })
  }
  names.sort(/* 최근 순 */)
  return [...new Set(names.map((n) => n.name))]
}
```

**약 목록**은 따로 저장하지 않고, 취소되지 않은 약 기록의 이름을 모아 만든다 (`CLAUDE.md` 데이터 규칙).

- **최근에 친 약이 앞**이다. 자주 쓰는 약을 찾기 쉽게 했다. 날짜가 같으면 나중에 입력한 쪽이 앞이다
- `r.pesticide?.trim()`: `?.`는 **값이 null이면 거기서 멈추고 `undefined`를 돌려준다.** 약 이름이 `null`이면 `.trim()`을 부르지 않는다. Java로는 `Optional.ofNullable(p).map(String::trim).orElse(null)`
- `if (name)`: 빈 글자(`""`), `null`, `undefined`는 모두 거짓으로 친다. 그래서 이름을 안 적었거나 빈칸만 적은 기록은 건너뛴다. Java에는 이런 규칙이 없어서 `name != null && !name.isEmpty()`로 쓴다
- `[...new Set(...)]`: 중복을 빼면서 **처음 나온 순서를 지킨다** (2단계의 구역 목록과 같은 방법, [[2026-10-22-React-컴포넌트와-props]] 3번). 최근 순으로 줄 세운 뒤 거르니 같은 이름은 가장 최근 것 하나만 남는다
- `b.workDate.localeCompare(a.workDate)`: 글자 비교. 음수/0/양수를 돌려준다. Java의 `b.compareTo(a)`

```ts
export function latestHarvestAmount(records, harvestId): HarvestAmountRecord | null
```

**수확량**: 수확 완료 기록 하나에 붙은 수확량 중 가장 나중에 입력한 것. 입력 화면에서 "이미 적은 양: 3박스 5단"을 보여줄 때 쓴다. 수확 완료 기록이 취소됐으면 수확량도 무시한다 (`CLAUDE.md` 규칙). 4단계 이력 화면에서도 쓸 수 있다.

### `harvestCalc.ts`의 `lastHarvestRecord`

```ts
export function lastHarvestRecord(records, houseNo): HarvestRecord | null {
  return lastOf(records, (r): r is HarvestRecord => r.type === 'harvest' && r.house_no === houseNo)
}
```

원래 `getHouseStatus` 안에 있던 "그 동의 마지막 수확 완료 기록 찾기"를 꺼내 공개했다. **수확량은 이 기록에 붙인다.** `getHouseStatus`가 수확 후 일수를 세는 기록과 수확량이 붙는 기록이 같은 함수에서 나오므로 서로 어긋날 일이 없다. `lastOf`는 [[2026-10-22-1단계-코드-읽기]] 3-3번.

### `today.ts`의 `nowTimestamp`

```ts
export function nowTimestamp(now: Date = new Date()): string {
  return now.toISOString()   // "2026-10-22T12:34:56.789Z"
}
```

기록의 `recorded_at`(입력한 시각)이다. 한 줄짜리지만 이 파일에 둔 이유: **현재 시각을 읽는 곳을 `today.ts` 한 곳으로 모은다**는 규칙 때문이다 ([[2026-10-22-2단계-코드-읽기]] 4번). 끝의 `Z`는 UTC라는 뜻이다. 날짜(`work_date`)와 달리 시각은 UTC로 둬도 된다. 비교할 때 `Date.parse`로 숫자로 바꾸기 때문이다 ([[2026-10-22-1단계-코드-읽기]] 3-2번).

### `types.ts`

```ts
pesticide: string | null // 약 이름. 안 적어도 된다 (null)
```

약 이름을 안 적어도 되게 했다 → [[결정기록]] "약 이름은 안 적어도 된다". `string | null`은 "글자 또는 null"이다. Java의 `String`은 원래 null이 될 수 있지만, TS는 `| null`을 적어야만 null을 허락한다. 그래서 `r.pesticide.trim()`처럼 쓰면 "null일 수 있다"는 빌드 에러가 나고, 위처럼 `?.`로 써야 한다.

## 6. `App.tsx`: 화면 전환

화면이 셋(목록, 기록 입력, 이력)뿐이라 **라우터 라이브러리 없이** "지금 화면" 값 하나(`screen`)로 정한다. 3단계에는 화면이 둘이라 "열린 동 번호"(`houseNo`) 하나였는데, 4단계에서 이력 화면이 생겨 `{ 동 번호, 어느 화면 }`으로 바꿨다. 자세한 것은 [[2026-10-22-4단계-코드-읽기]] 4번.

```tsx
const records = useRecords()
const [screen, setScreen] = useState(() => screenFromHistory(history.state))   // null이면 목록
...
if (records === undefined) return null

const house = HOUSES.find((h) => h.no === screen?.houseNo)

return (
  <>
    {screen === null || house === undefined ? (
      <HouseList ... onSelectHouse={(no) => open({ houseNo: no, view: 'form' })} />
    ) : screen.view === 'form' ? (
      <RecordForm key={house.no} house={house} ... onSaved={handleSaved} onCancel={() => history.back()} ... />
    ) : (
      <History ... />
    )}
    {message !== null && <p className="toast" role="status">{message}</p>}
  </>
)
```

- **`screen`이 `null`이면 목록, `{ houseNo: 3, view: 'form' }`이면 3동 기록 화면이다.** Spring으로 치면 `/houses`와 `/houses/{no}/records/new` 같은 주소를 컨트롤러 하나가 `if`로 가르는 셈이다
- **동을 누를 때 `history.pushState`로 방문 기록을 하나 쌓는다.** 그래서 폰의 뒤로 가기 버튼을 누르면 앱이 꺼지지 않고 목록으로 돌아온다. "‹ 목록" 버튼과 저장 후 돌아가기도 모두 `history.back()`을 써서, 돌아가는 길을 하나(`popstate` 이벤트)로 모았다 → [[2026-10-22-브라우저-history와-뒤로-가기]]
- **목록으로 돌아오면 보던 스크롤 위치로 되돌린다.** 25동을 기록하고 왔는데 맨 위로 튀면 다시 내려가야 한다. 열 때 `scrollY`를 `useRef`에 적어 두고, 돌아오면 `useLayoutEffect`에서 그 자리로 보낸다 → [[2026-10-22-React-state와-이벤트]] 5번
- **저장 알림("3동 약 저장했어요")은 3초 뒤 사라진다.** `useEffect` + `setTimeout`. 다른 동을 바로 열면 알림이 저장 버튼을 가리지 않게 지운다
- `if (records === undefined) return null`: IndexedDB를 처음 읽는 아주 짧은 동안은 아무것도 안 그린다. 빈 배열로 그리면 그 순간 모든 동이 "수확 기록 없음"으로 깜빡이기 때문이다
- `key={house.no}`: 다른 동의 기록 화면으로 바뀌면 입력하던 내용을 버리고 처음부터 시작하게 한다 → [[2026-10-22-React-state와-이벤트]] 5번
- **새로고침해도 보던 화면이 남는다.** `history.state`에 화면 값을 넣어 뒀기 때문에, 처음 값을 거기서 읽는다

### `buildRecord`: 고른 내용 → 새 기록

```tsx
function buildRecord(): { record: NewRecord; label: string } | null {
  if (!dateOk) return null
  const base = { house_no: house.no, work_date: workDate, memo: null }

  const used = toAmount(amount)   // 9단계: 적은 양 (15번)
  switch (kind) {
    case 'spray': {
      const name = pesticide.trim()
      return {
        record: { ...base, type: 'spray', pesticide: name || null, amount_ml: used },
        label: name ? `약(${name})` : '약',
      }
    }
    case 'top_dressing': ...   // 7단계: 비료 이름 (13번), 9단계: 포 수 (15번)
    case 'fertigation': ...
    ...
    case 'harvest':
      if (harvestStep === 'harvest' && cycle >= 1) {
        return { record: { ...base, type: 'harvest', cycle_days: cycle }, label: '수확 완료' }
      }
      ...
      return null
    ...
  }
}

const built = buildRecord()
...
<button type="submit" className="save" disabled={built === null || saving}>
```

- **"저장해도 되는지"와 "무엇을 저장할지"를 한 함수가 정한다.** 덜 골랐으면 `null`을 돌려주고, 그러면 저장 버튼이 꺼진다. 저장 가능 조건과 저장 내용을 따로 쓰면 둘이 어긋날 수 있어서 하나로 묶었다
- `label`은 저장 후 알림("3동 **약(가약)** 저장했어요")에 쓴다
- `switch`는 Java와 같다. `case 'spray': { ... }`처럼 중괄호를 친 건 그 안에서 `const name`을 만들기 위해서다 (Java도 같음)
- `name || null`: 앞이 빈 글자면 뒤(`null`)를 쓴다. "안 적었으면 null로 저장"
- `{ ...base, type: 'spray', ... }`: 공통 항목을 펼쳐 넣고 종류별 항목을 더한다 ([[2026-10-22-Vitest-테스트와-순수-함수]] 3번의 테스트 도우미와 같은 모양)
- 타입 검사도 된다. `type: 'harvest'`인데 `cycle_days`를 빠뜨리면 빌드 에러가 난다
- `buildRecord`는 컴포넌트 함수 **안에** 있다. 그래서 `kind`, `pesticide`, `house` 같은 값을 인자로 받지 않고 바로 쓴다. 이렇게 바깥 함수의 변수를 그대로 쓰는 함수를 **클로저**라고 한다. Java 람다가 바깥의 `final` 변수를 쓰는 것과 비슷하다

### 저장

```tsx
async function handleSubmit(e: FormEvent) {
  e.preventDefault()
  if (built === null || saving) return
  setSaving(true)
  setError(null)
  try {
    await addRecord(built.record)

```

- `e.preventDefault()`: `<form>`은 원래 제출하면 페이지를 새로 불러온다 (서버로 보내는 HTML 기본 동작). 그걸 막고 직접 처리한다
- **저장하는 동안 버튼을 끈다(`saving`).** 장갑 낀 손으로 두 번 눌러 같은 기록이 두 개 생기지 않게 한다
- 저장이 끝나면 `onSaved`로 App에 알린다. **기록 화면은 목록으로 돌아가는 법을 모른다.** App이 정한다
- `<form>`으로 감쌌기 때문에 숫자 칸에서 폰 키보드의 "완료/이동" 키를 눌러도 저장된다

### 작은 도우미

```tsx
function Choice({ selected, onClick, children }: { ...; children: ReactNode }) {
  return (
    <button type="button" className="choice" aria-pressed={selected} onClick={onClick}>
      {children}
    </button>
  )
}

function digitsOnly(value: string, maxLength: number): string {
  return value.replace(/\D/g, '').slice(0, maxLength)
}
```

- **`Choice`: 고르는 버튼 하나.** 종류, 수확 단계, 약·비료 이름, 문제 모두 같은 모양이다
  - `children`: `<Choice>약</Choice>`처럼 태그 사이에 넣은 내용이다. Thymeleaf 프래그먼트에 HTML 덩어리를 넘기는 것과 비슷하다
  - `aria-pressed`: "눌린 상태"를 화면 읽기 기능에 알리는 HTML 속성이다. CSS도 이 값으로 고른 버튼을 초록으로 칠한다(`.choice[aria-pressed='true']`). 그래서 모양을 위한 클래스를 따로 두지 않았다
  - `type="button"`: `<form>` 안의 버튼은 기본이 "제출"이라, 안 적으면 종류만 골라도 저장된다. 그래서 저장 버튼만 `type="submit"`이다
- **`digitsOnly`: 숫자 칸에서 숫자 아닌 글자를 지운다.** `/\D/g`는 정규식으로 "숫자가 아닌 모든 글자"다. Java의 `value.replaceAll("\\D", "")`
  - 숫자 칸은 `<input type="number">` 대신 `inputMode="numeric"`(글자 칸 + 숫자 키패드)을 썼다. `type="number"`는 `1e3` 같은 글자가 들어가고, PC에서는 마우스 휠에 값이 바뀌는 등 말썽이 많다. 우리는 0 이상의 정수만 필요해서 글자 칸에 숫자만 남기는 쪽이 단순하다

- **상자 어디를 눌러도 달력이 열린다** (`openDatePicker` → `showPicker()`). 폰에 따라 투명한 칸이 상자 전체를 덮지 못해 "바꾸기"가 안 눌렸기 때문이다
- **PC(마우스)에서는 투명한 칸이 눌려도 앱이 직접 연다** (`matchMedia('(pointer: fine)')`). PC 크롬은 날짜 칸의 달력 아이콘을 눌러야만 열리는데, 그 아이콘도 투명해서 PC에서는 눌러도 반응이 없었다
- 겹쳐 놓는 CSS, `showPicker`, PC와 폰의 차이, 클릭이 바깥 상자로 전해지는 것(폰에서 `e.target === input`이면 그냥 두는 이유) → [[2026-10-23-날짜-칸-덮기와-클릭-이벤트-전파]]

- 기본은 오늘이다 (`CLAUDE.md` 원칙). 어제 일을 오늘 적을 수 있게 지난 날짜는 고를 수 있다
- `max={today}`로 앞날을 막고, 빈칸이거나 앞날이면 저장 버튼이 꺼진다
- 옆에 "오늘 / 어제 / N일 전"을 보여 준다(`labels.ts`의 `relativeDay`, 이력 화면도 같이 씀). 날짜 숫자만 보면 오늘인지 바로 알기 어렵다
- `type="date"` 칸은 `"2026-10-22"` 형식 글자를 돌려준다. 우리 날짜 규칙과 같아서 바꿀 필요가 없다

- `margin: 0 -0.4rem`과 `padding: 0 0.4rem`: 바깥으로 0.4rem 넓히고 안쪽으로 0.4rem 들여서, 글자 위치는 그대로 두고 회색 바탕만 양옆으로 넓힌다. 회색이 글자에 딱 붙지 않게 하려는 것이다
- 구분선은 `.house-rows li + li`로 옮겼다. `.house-row`가 이제 `<li>` 안의 버튼이라 "바로 앞 형제" 관계가 `<li>`끼리이기 때문이다

### 아래에 붙은 저장 버튼 (`RecordForm.css`)

```css
.save-bar {
  position: sticky;
  bottom: 0;
  background: var(--bg);
}
.form-card { scroll-margin-bottom: 6rem; }
```

- `position: sticky; bottom: 0`: 평소에는 제자리에 있다가, 화면이 길어 스크롤하면 **화면 아래에 붙어 있는다.** 저장 버튼이 항상 보인다
- `scroll-margin-bottom: 6rem`: 카드로 스크롤할 때 아래에 6rem 여유를 둔다. 안 그러면 카드 끝이 저장 버튼 뒤에 걸린다

### 고른 버튼

```css
.choice[aria-pressed='true'] {
  border-color: var(--primary);
  background: var(--primary-weak);
  color: var(--primary-strong);

```

`[속성='값']`은 그 속성 값을 가진 태그만 고르는 선택자다. 목록의 "수확 가능" 배지와 같은 초록 계열이다.

### 그 밖에

- `box-sizing: border-box` (`.text-input`): 너비 100%에 테두리·안쪽 여백까지 포함한다. 없으면 칸이 카드 밖으로 삐져나온다
- 버튼·입력 칸 높이는 `3rem`(20px 기준 60px) 이상. 장갑 낀 손 기준이다
- 고르는 버튼(`.choice`)의 양옆 안쪽 여백은 `0.3rem`으로 작다. 360px 폭 폰에서 한 줄에 셋일 때 "웃거름"이 두 줄로 꺾여서 줄였다. 높이와 글자 크기는 그대로다
- 날짜는 "날짜 오늘" 아래에 칸을 꽉 차게 둔다. 한때 한 줄(`[날짜 오늘] [칸]`)로 붙였다가 칸이 좁아져 되돌렸다
- 가장 작은 글자는 `0.8rem`(16px)이다. 2단계에서 정한 기준을 지킨다 → [[결정기록]] "문제 표시는 아이콘에 글자를 붙인다"
- 새 색 `--line-strong`(`index.css`): 버튼·입력 칸 테두리. 흰 카드 위에서 보이도록 구분선(`--line`)보다 진하다

## 13. 7단계 (2026-10-26): 웃거름·관비에 비료 이름

웃거름·관비를 누르면 약처럼 비료 이름을 고르거나 적는다 (안 적어도 된다). 둘을 "비료" 하나로 합치지는 않았다 → [[결정기록]] "웃거름·관비는 합치지 않고 비료 이름만 적는다"

### 바뀐 파일

```
supabase/records.sql             ✎ fertilizer 칸 (처음부터 만드는 곳용)
supabase/records-fertilizer.sql  ★ 이미 있는 표에 칸 더하기 (진짜 Supabase에서 한 번 실행)
src/domain/types.ts              ✎ 웃거름·관비에 fertilizer?, FertilizerType
src/domain/recordQueries.ts      ✎ fertilizerNames, 약·비료가 같이 쓰는 recentNames
src/pages/RecordForm.tsx         ✎ NamePicker(약·비료 이름 칸), 비료 카드, chooseKind
src/pages/History.tsx            ✎ 웃거름·관비 옆에 비료 이름
src/data/syncService.ts          ✎ RecordRow.fertilizer, fromRow
```

### `types.ts`: 없을 수도 있는 항목 `?:`

```ts
export interface TopDressingRecord extends RecordBase {
  type: 'top_dressing'
  fertilizer?: string | null
}

export type FertilizerType = 'top_dressing' | 'fertigation'
```

- 약은 `pesticide: string | null`(항목은 꼭 있고 값이 `null`일 수 있음)인데, 비료는 `fertilizer?: string | null`(**항목 자체가 없을 수도 있음**)이다. 7단계 전에 폰(IndexedDB)에 저장한 웃거름 기록에는 이 항목이 아예 없기 때문이다. IndexedDB는 객체를 통째로 저장해서, 새 버전이 나와도 옛 기록이 새 모양으로 바뀌지 않는다 ([[2026-10-22-IndexedDB와-Dexie]])
- 타입을 사실대로 적어 두면, 읽는 쪽에서 "없음"을 빠뜨렸을 때 빌드 에러가 난다. 그래서 읽을 때 `r.fertilizer ?? null`(이력)이나 `?.trim()`(`recentNames`)으로 "없음"(`undefined`)과 `null`을 같이 다룬다. `??`는 [[2026-10-23-6단계-코드-읽기]] 4번
- Java에는 "항목이 없음"이 없다. 필드는 늘 있고 값이 `null`일 뿐이다. 가장 가까운 것은 JPA 엔티티에 컬럼을 새로 더했을 때 옛 행의 값이 `null`인 것이다. Java로 쓰면 그냥 `String fertilizer; // null 가능`이다
- `FertilizerType`: 비료 이름을 적는 두 종류만 모은 타입이다. 함수가 "웃거름이나 관비만" 받게 할 때 쓴다. Java라면 `enum FertilizerType { TOP_DRESSING, FERTIGATION }`

### `recordQueries.ts`: 함수를 인자로 받는 `recentNames`

```ts
export function pesticideNames(records) {
  return recentNames(records, (r) => (r.type === 'spray' ? r.pesticide : null))
}

export function fertilizerNames(records, type: FertilizerType) {
  return recentNames(records, (r) =>
    (r.type === 'top_dressing' || r.type === 'fertigation') && r.type === type ? r.fertilizer : null,
  )
}

function recentNames(records, nameOf: (r: FarmRecord) => string | null | undefined): string[] {
  // 3단계의 pesticideNames 몸통 그대로: 취소 제외 → 이름 없는 기록 건너뜀 → 최근 순 → 같은 이름은 한 번 (5번)
}
```

- 약 목록과 비료 목록은 "기록에서 이름 뽑기"만 다르고 나머지는 같다. 그래서 같은 부분을 `recentNames`로 빼고, **다른 부분(이름 뽑기)만 함수로 넘긴다**
- `nameOf: (r: FarmRecord) => string | null | undefined`: "기록을 받아 이름(또는 없음)을 돌려주는 함수"라는 타입이다. Java의 `Function<FarmRecord, String>`과 같다

  ```java
  static List<String> recentNames(List<FarmRecord> records, Function<FarmRecord, String> nameOf) { ... }

  static List<String> pesticideNames(List<FarmRecord> records) {
      return recentNames(records, r -> r instanceof SprayRecord s ? s.pesticide() : null);
  }
  ```
- `(r) => (... ? r.pesticide : null)`: 화살표 함수다 ([[2026-10-22-React-state와-이벤트]]). Java 람다 `r -> ...`와 같다
- **`r.type === 'top_dressing' || r.type === 'fertigation'`을 먼저 쓴 이유:** `r.type === type`만 쓰면 TypeScript가 `r`을 웃거름·관비 기록으로 좁히지 못해서 `r.fertilizer`에 빌드 에러가 날 수 있다. `type`이 글자 하나가 아니라 "둘 중 하나"인 변수라서다. 글자를 직접 비교하면 확실히 좁혀진다 ([[2026-10-22-TypeScript-구별된-유니온]])
- `pesticideNames`는 이름과 동작이 그대로라 테스트도 그대로 통과한다. 겉은 그대로 두고 속만 나눈 것이다 (리팩터링)
- **웃거름과 관비는 목록을 따로 모은다.** 웃거름에 쓰는 비료와 관비(물에 타서 주는 비료)가 한 목록에 섞이면 고르기 헷갈려서다

  ```sql
  alter table public.records add column fertilizer text;
  grant insert (fertilizer) on public.records to authenticated;
  ```
  - `grant insert (칸 목록)`은 칸마다 허락한다 ([[2026-10-23-환경-변수와-Supabase-권한]]). 새 칸은 목록에 없으니 따로 더한다. 조회(`grant select`)는 표 전체에 줬으므로 새 칸도 저절로 보인다
  - 칸을 먼저 더해도 옛 버전 폰은 괜찮다. 옛 버전은 그 칸을 보내지 않고(빈 값으로 저장됨), 받을 때도 모르는 칸은 버린다
- **새 버전을 아직 못 받은 폰**은 다른 사람이 적은 비료 이름을 빼고 기록을 받는다 (옛 `fromRow`가 모르는 칸을 버림). 7단계 때는 새 버전을 받은 뒤에도 그 기록이 이미 폰에 있어서 다시 받지 않으므로 이름이 채워지지 않았다 (이력에 이름이 안 보일 뿐 일수 계산에는 영향이 없음). **9단계 새 버전이 처음 열릴 때 서버 기록을 처음부터 다시 받아 채운다** ([[2026-10-23-6단계-코드-읽기]] 9번). 새 버전이 언제 뜨는지는 [[2026-10-23-PWA와-서비스-워커]] 3번

### 옛 버전 앱이 새 기록을 받으면

- 8단계 전 앱의 이력 화면은 `PROBLEM_TAG[r.problem].icon`으로 그린다. `PROBLEM_TAG['other']`는 없어서(`undefined`) `.icon`을 읽다가 에러가 난다. 이 앱에는 에러를 잡아 주는 장치(Error Boundary)가 없어서, React가 화면 전체를 지운다 → **하얀 화면**
- 목록 화면은 옛 버전도 괜찮다. 옛 계산은 배수·균사만 찾아서 `'other'` 기록은 그냥 지나친다
- 그래서 **새 버전을 모든 폰이 받기 전에는 직접 적은 문제를 저장하지 않는다.** 취소된 기록은 옛 버전도 이력에 그리지 않으므로, 시험할 때는 오프라인에서 저장하고 **오프라인인 채로 취소한 뒤** 온라인으로 돌린다
- 일반적인 이야기는 [[2026-10-23-PWA와-서비스-워커]] 6번

### 서버 표 바꾸기: `records-problem-name.sql`

```sql
alter table public.records drop constraint records_problem_check;
alter table public.records add constraint records_problem_check
  check (problem in ('drainage','mycelium','other'));
alter table public.records add column problem_name text;
grant insert (problem_name) on public.records to authenticated;
```

### `types.ts`: 종류마다 다른 양 칸


- `?:`는 7단계 비료 이름과 같은 이유다. 9단계 전에 저장한 기록에는 이 항목이 아예 없다 (13번 `?:`)

### `recordQueries.ts`: `lastUsedAmount`

```ts
export function lastUsedAmount(records, type: AmountType, name: string): number | null {
  let latest: FarmRecord | null = null
  let latestAmount: number | null = null
  for (const r of activeRecords(records)) {
    if (r.type !== type) continue
    const amount = amountOf(r)
    if (amount === null || nameOfAmount(r)?.trim() !== name.trim()) continue
    if (latest === null || isLater(r, latest)) {
      latest = r
      latestAmount = amount
    }
  }
  return latestAmount
}

function amountOf(r: FarmRecord): number | null {
  if (r.type === 'spray' || r.type === 'fertigation') return r.amount_ml ?? null
  if (r.type === 'top_dressing') return r.bags ?? null
  return null
}
```

- 취소되지 않은 그 종류 기록 중 **같은 이름이고 양을 적은 것**만 보고, 그중 마지막 것의 양을 돌려준다. "마지막"은 일수 계산과 같은 `isLater`(작업 날짜가 늦은 것, 같으면 나중에 입력한 것, [[2026-10-22-1단계-코드-읽기]])다
- **모든 동**에서 찾는다. 3동에 "가약 20ml"를 쳤으면 7동에서 가약을 골라도 20이 채워진다. 같은 약은 보통 같은 양을 쓴다고 봤다 (확인 필요)
- 양을 안 적은 기록은 건너뛴다. 가약을 20ml로 한 번, 그다음 양 없이 한 번 적었으면 20이 채워진다
- `amountOf`, `nameOfAmount`: "기록에서 양(이름) 꺼내기"를 종류마다 나눴다. 밖으로 내보내지 않는(`export` 없는) 도우미 함수다. Java의 `private static`
- `r.amount_ml ?? null`: 항목이 없으면(`undefined`, 9단계 전 기록) `null`로 맞춘다 ([[2026-10-23-6단계-코드-읽기]] 4번 `??`)
- 처음엔 이름을 `lastAmount`로 했는데, `RecordForm.tsx`에 이미 같은 이름의 변수(마지막 수확의 수확량)가 있어서 빌드 에러가 났다. 그래서 `lastUsedAmount`로 바꿨다. JS에서는 import한 이름과 함수 안 변수 이름이 같으면, 함수 안에서는 변수가 import를 가린다 (Java의 지역 변수가 필드를 가리는 것과 같음)

### 작은 도우미 두 개

```tsx
function decimalOnly(value: string, maxLength: number): string {
  const [whole, ...rest] = value.replace(',', '.').replace(/[^\d.]/g, '').split('.')
  const int = whole.slice(0, maxLength)
  return rest.length === 0 ? int : `${int}.${rest.join('').slice(0, 1)}`
}

function toAmount(typed: string): number | null {
  const n = Number(typed)
  return typed === '' || !Number.isFinite(n) || n <= 0 ? null : n
}
```

- `decimalOnly`: 숫자와 점 하나만 남기고, 점 아래는 한 자리까지 ("1.55" → "1.5", "1.2.3" → "1.2")
  - `replace(',', '.')`: 폰 설정에 따라 소수점 자판이 쉼표(,)일 수 있어서 점으로 바꾼다
  - `/[^\d.]/g`: 숫자(`\d`)와 점(`.`)이 **아닌**(`^`) 글자 모두(`g`). Java의 `replaceAll("[^\\d.]", "")`
  - `const [whole, ...rest] = ....split('.')`: 배열을 풀어 담는다 (구조 분해). 첫 칸은 `whole`, 나머지는 몽땅 배열 `rest`로. "1.5" → `whole = '1'`, `rest = ['5']`. "12" → `rest = []`. Java에는 없는 문법이다 (`String[] parts = s.split("\\."); String whole = parts[0];`처럼 하나씩 꺼낸다)
- `toAmount`: 적은 글자 → 숫자. **비었거나 0이면 `null`(안 적은 것)**이다. "0ml"는 적을 이유가 없어서 안 적은 것과 같게 봤다
  - `Number('.')`는 `NaN`(숫자가 아님)이다. `Number.isFinite(n)`이 `NaN`을 거른다. Java의 `Double.isFinite(n)`
- 저장할 때는 `buildRecord`가 `const used = toAmount(amount)`를 각 종류의 칸(`amount_ml` 또는 `bags`)에 넣는다 (7번 `buildRecord`, 13번)

### 하나 따라가 보기: 3동 "가약 20ml" → 7동에서 가약 고르기

1. 3동 → [약] → 약 카드에 이름 칸과 "원액 양 [ ] ml" 칸
2. 이름 칸에 "가약", 양 칸에 "20" → `pesticide = '가약'`, `amount = '20'`
3. [저장] → `buildRecord`: `toAmount('20')` = 20 → `{ type: 'spray', pesticide: '가약', amount_ml: 20 }` → "3동 약(가약) 저장했어요"
4. 7동 → [약] → [가약] 버튼 → `onPick('가약')` → `pickName('spray', '가약', setPesticide)` → `lastUsedAmount(records, 'spray', '가약')` = 20 → 양 칸에 "20"이 채워져 있다
5. 바꿀 게 없으면 [저장]. 버튼 세 번(약 → 가약 → 저장)으로 7동 "가약 20ml"
6. 7동 이력: "약 가약 20ml"

비료는: 5동 → [비료] → [가비료] → (지난번에 반 포였으면 [반 포]가 이미 초록) → [저장] → "5동 비료(가비료) 저장했어요" → 이력 "비료 가비료 반 포"
