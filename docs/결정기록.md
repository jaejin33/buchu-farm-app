## 2026-10-21 백엔드를 Spring 대신 Supabase로
- 결정: 당분간 별도 백엔드 서버 없이 Supabase(PostgreSQL + Auth)를 쓴다. 화면은 React + TypeScript
- 이유: 개발에 합류할 친구가 Spring을 모르고, React+TypeScript·Vercel·Supabase 경험이 있음
- 이전: MVP는 Spring Boot(REST API) + PostgreSQL, 클라우드 가상 서버
- 비고: 나중에 서버를 바꿀 수 있도록 Supabase 코드는 `src/data/` 안에만 둔다

## 2026-10-21 프로토타입도 서버에 기록을 모은다
- 결정: 폰 안에만 저장하지 않고 Supabase로 동기화한다
- 이유: 형 폰에 입력된 기록을 집에서도 확인할 수 있어야 함
- 이전: 서버 없이 폰 안에만 저장하는 프로토타입

## 2026-10-21 오프라인 처리를 처음부터 포함
- 결정: 폰 안(IndexedDB)에 먼저 저장하고, 연결되면 서버로 보낸다
- 이유: 하우스 안 휴대폰 인터넷이 가끔 끊김

## 2026-10-21 사용자는 아버지와 형 둘 다
- 결정: 앱 사용자는 아버지와 형, 각자 휴대폰
- 이전: 프로토타입은 형 한 명으로 한정
- 확인 필요: 실제로 누가 입력할지. 영농일지는 아버지가 혼자 관리하고 형은 말로 보고함

## 2026-10-21 기록은 추가만 하고 수정·삭제하지 않는다
- 결정: 잘못 입력한 기록은 취소 기록을 새로 추가한다. 수정은 "취소 + 새 기록"
- 이유: 두 사람이 오프라인에서 각자 입력해도 서로 덮어쓰지 않게

## 2026-10-21 약 기록에는 수확 전 일수를 복사해 저장한다
- 결정: 약 기록마다 그때 고른 약의 수확 전 일수(`phi_days`)를 함께 저장한다
- 이유: 나중에 약 정보가 바뀌어도 지난 기록의 수확 가능일 계산이 달라지지 않게, 오프라인에서도 계산되게
- 보류: 약 목록 방식(약별 기준 데이터 vs 기록에서 모으기)은 입력자와 쓰는 약 종류 수를 확인한 뒤 앱 3단계에서 결정

## 2026-10-21 문서는 옵시디언 보관함 `docs/`에, 정리는 직접 요청할 때만
- 결정: 레포의 `docs/`를 옵시디언 보관함으로 쓰고, 세션을 마칠 때 `/wrap-up`으로 정리한다

## 2026-10-22 수확 기록이 없는 동은 "기록 없음"(⚪)으로 표시
- 결정: (취소되지 않은) 수확 기록이 없으면 약·웃거름·관비 기록이 있어도 ⚪ 기록 없음으로 표시한다. 약 대기 중이면 🔴 약 대기가 우선한다
- 이유: 수확 기록이 없으면 다음 수확 예정일을 계산할 근거가 없다. 근거 없이 🟢 수확 가능을 띄우지 않는 쪽이 안전하다. 글자 그대로 "기록이 하나도 없을 때만 ⚪"로 하면 시즌 초에 약만 친 동이 모두 🟢로 보인다
- 이전: `CLAUDE.md`에 "기록 없음"의 기준이 정해져 있지 않았음
- 비고: [[2026-10-22-TypeScript-구별된-유니온]], [[2026-10-22-Vitest-테스트와-순수-함수]]

## 2026-10-22 하우스 문제 상태는 "있다/없다"만
- 결정: 배수·균사 문제는 수치나 정도 없이 동마다 있다/없다만 둔다. 카드에 💧(배수), 🍄(균사)로 표시한다
- 이유: 농민이 균사가 얼마나 많은지를 수치로 재기는 어렵다. 필요한 것은 "이 동은 문제가 있다"는 표시다
- 비고: 고압 살수기 조치 결과에 따라 상태가 바뀔 수 있다. 바뀌면 `src/config/houses.ts`를 고쳐 다시 배포한다

## 2026-10-22 하우스 구역은 6개
- 결정: 1구역 1~4동, 2구역 5~10동, 3구역 11~13동, 4구역 14~16동, 5구역 17~20동, 6구역 21~25동
- 확인 필요: 구역을 부르는 이름 (지금은 "1구역"처럼 번호로 붙임), 💧·🍄 문제가 있는 동 번호 (지금은 임시 값)

## 2026-10-22 구역·하우스 설정 화면은 만들지 않는다
- 결정: 하우스 정보는 계속 `src/config/houses.ts`에 두고, 앱 안에서 고치는 설정 화면은 만들지 않는다
- 이유: 우리 농장 하나만 쓰고 25동이 거의 바뀌지 않는다. 설정 화면을 만들면 설정 저장, 두 폰 사이 동기화, 동 번호를 바꿨을 때 지난 기록 처리까지 필요해진다. 이번 프로토타입의 검증 목적("오늘 벨 수 있는지 한눈에")과 관계가 없다
- 비고: 다른 농가 대상(B)으로 넓힐 때 다시 검토한다. 그때는 하우스 정보를 DB로 옮기고, 기록이 동 번호 대신 하우스 고유 id·농장 id를 가리키게 바꿔야 한다. 화면(`HouseList`)은 `House[]` 배열만 받으므로 그대로 쓸 수 있다

## 2026-10-22 하우스 목록 정렬
- 결정: 구역별로 묶고, 구역 안에서는 "벨 수 있는 날"이 가까운 순으로 놓는다
  - 벨 수 있는 날 = 약 때문에 벨 수 있는 날과 다음 수확 예정일 중 늦은 날 (`harvestableDate`)
  - 수확 기록이 없는 동은 약 대기 중이어도 구역 맨 뒤
  - 날짜가 같으면 동 번호 순. 이미 수확 가능한 동은 오래 기다린 동이 앞에 온다
- 이유: `CLAUDE.md`의 "구역별로 묶은 카드"와 "벨 수 있는 날이 가까운 순"을 함께 지키기 위해
- 이전: 두 규칙을 어떻게 함께 적용할지 정해져 있지 않았음
- 비고: 구역 순서는 `houses.ts`에 적힌 순서다. 한 줄에 놓이는 카드 수는 화면 폭에 따라 정해지고 구역 크기에 맞추지 않는다 (폰 3장, PC 5장). 카드를 더 작게 해서 6동을 한 줄에 넣으면 장갑 낀 손으로 누르기 어렵다

## 2026-10-22 화면 크기는 기준 글자 크기 하나로 조정
- 결정: CSS 크기는 `rem` 단위로 적고, `src/index.css`의 기준 글자 크기(지금 16px) 하나로 화면 전체 크기를 조정한다. 실제 크기는 5.5단계에서 아버지께 보여드린 뒤 정한다
- 이유: 아버지의 휴대폰 사용 수준이 미확정이다. 지금은 크기를 나중에 쉽게 바꿀 수 있게만 해 둔다
- 비고: 상태는 색과 글자 라벨("약 대기" 등)을 함께 표시하고, 밝은 화면 하나만 쓴다. 햇빛 아래에서 보기와 색약을 고려했다. [[2026-10-22-CSS-rem-단위]]

## 2026-10-22 화면은 기록을 props로 받는다
- 결정: `HouseList`는 하우스 목록·기록·오늘 날짜를 props로 받는다. 2단계에서는 `App.tsx`가 가짜 기록(`src/data/fakeRecords.ts`)을 넘긴다. 한국 시간 기준 "오늘"은 `src/domain/today.ts` 한 곳에서만 구한다
- 이유: 3단계에서 가짜 기록을 IndexedDB로 바꿀 때 화면 코드는 그대로 두고 `App.tsx`만 고치면 되게 하기 위해
- 비고: 실제 기록 id를 만드는 `crypto.randomUUID()`는 https 주소나 localhost에서만 동작한다. 폰에서 PC 개발 서버(`http://192.168...`)로 접속하면 동작하지 않아서 가짜 기록은 `fake-1` 같은 id를 쓴다. 3단계에서 폰으로 시험할 방법을 정해야 한다 (확인 필요). [[2026-10-22-React-컴포넌트와-props]]
