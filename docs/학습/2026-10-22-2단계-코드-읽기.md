## 2. `types.ts`: `House` 타입

```ts
export type HouseProblem =
  | 'drainage' // 💧 배수가 안 됨
  | 'mycelium' // 🍄 버섯균사가 많음

export interface House {
  no: number
  zone: string
  crop: string
}
```

- **`House`에는 바뀌지 않는 정보만 둔다.** 번호·구역·작물이다
- **문제 상태는 여기 없다.** 문제 있는 동은 수시로 바뀌어서 `problem` 기록으로 남기고, 계산 결과(`getHouseStatus(...).problems`)로 받는다. 처음엔 2단계에서 `House`에 `problems` 배열을 두었다가 2.7단계에서 뺐다 → [[결정기록]] "하우스 문제 상태는 houses.ts가 아니라 기록으로"
- `HouseProblem`(문제 종류)은 그대로 여기 있다. 문제 기록과 화면이 함께 쓰는 이름이라서다. **문제 상태는 "있다/없다"만 둔다.** 정도를 숫자로 두지 않았다 → [[결정기록]] "하우스 문제 상태는 있다/없다만"
- `crop`(작물)은 지금 모두 `'부추'`지만 넣어 두었다. 형이 다른 작물도 생각하고 있어서다 ([[진행기록]] 4번)

## 4. `domain/today.ts`: 한국 시간 "오늘"

```ts
const KST_OFFSET_MS = 9 * 60 * 60 * 1000

export function todayInKorea(now: Date = new Date()): string {
  return new Date(now.getTime() + KST_OFFSET_MS).toISOString().slice(0, 10)
}
```

한 줄짜리지만 원리가 있다.

1. `now.getTime()`: 1970-01-01 00:00 UTC부터 지난 밀리초. **세계 어디서나 같은 숫자**다 (Java의 `Instant.toEpochMilli()`)
2. 여기에 9시간을 더한다
3. `.toISOString()`은 항상 **UTC 기준**으로 `"2026-10-22T00:30:00.000Z"` 같은 글자를 만든다. 9시간을 미리 더했으니 이 글자가 곧 한국 시각이다
4. `.slice(0, 10)`: 앞 10글자 `"2026-10-22"`만 자른다 (Java의 `substring(0, 10)`)

예: UTC `2026-10-21 15:00` + 9시간 = `2026-10-22 00:00` → `"2026-10-22"`. 한국 자정에 날짜가 바뀐다. 테스트(`today.test.ts`)가 이 경계를 지킨다.

Java로는 `LocalDate.now(ZoneId.of("Asia/Seoul")).toString()` 한 줄이다. JS에는 시간대를 지정해 날짜만 꺼내는 쉬운 기본 기능이 없어서 이렇게 했다.

**왜 따로 파일을 만들었나:** `harvestCalc.ts`는 "오늘"을 인자로 받고 현재 시각을 직접 읽지 않는다 ([[2026-10-22-Vitest-테스트와-순수-함수]] 1번). 그러면 누군가는 현재 시각을 읽어야 한다. 그 일을 **이 파일 한 곳에만** 모았다. 현재 시각을 읽는 곳이 여기저기 흩어지면, 화면 일부는 어제 날짜, 일부는 오늘 날짜로 계산되는 일이 생길 수 있다.

`now: Date = new Date()`는 기본값이 있는 인자다. 앱에서는 `todayInKorea()`처럼 비워서 부르면 현재 시각을 쓰고, 테스트에서는 `todayInKorea(new Date('2026-10-21T15:00:00Z'))`처럼 시각을 넣어 고정한다. Spring에서 `Clock`을 주입하는 것과 같은 생각이다.

export const DEFAULT_CYCLE_DAYS = 35

## 6. `data/fakeRecords.ts`: 가짜 기록

3단계에서 IndexedDB를 붙이면 지울 파일이다. 그래도 읽을 거리가 있다.

### 왜 날짜를 "며칠 전"으로 만드나

`harvest(1, '2026-09-17')`처럼 날짜를 고정해 두면, 시간이 지나 다음 달에 열었을 때 모든 동이 🟢가 된다. 그래서 **오늘을 받아서 "오늘로부터 며칠 전"으로** 만든다. 언제 열어도 여러 상황이 골고루 보인다.

```ts
harvest(1, 40), // 🟢 수확 후 40일
harvest(3, 33), // 수확 후 33일
harvest(6, 38), spray(6, 2), // 🟢 수확 후 38일, 약 후 2일
harvest(17, 38, 40), // 수확 후 38일 (이 동은 40일로 적음 → 아직 🟢 아님)
```

각 줄 오른쪽 주석이 화면에 나와야 할 내용이다. 화면을 보고 주석과 다르면 어딘가 잘못된 것이다. 17번 동은 기본값 대신 40일을 적은 경우를 보여준다. 3번 동(33일, 기본값 35일)보다 오래됐는데도 🟢가 아니다.

### 함수 안의 함수 (클로저)

```ts
export function makeFakeRecords(today: string): FarmRecord[] {
  let seq = 0

  function base(houseNo: number, daysAgo: number) {
    seq += 1
    const work_date = addDays(today, -daysAgo)
    return { id: `fake-${seq}`, house_no: houseNo, work_date, ... }
  }

  const harvest = (houseNo: number, daysAgo: number, cycleDays = DEFAULT_CYCLE_DAYS): FarmRecord => ({
    ...base(houseNo, daysAgo),
    type: 'harvest',
    cycle_days: cycleDays,
  })
  ...
}
```

- `base`, `harvest`, `spray` 같은 도우미 함수가 `makeFakeRecords` **안에** 있다. 그래서 바깥 함수의 `today`와 `seq`를 인자로 받지 않고 바로 쓴다. 이것을 **클로저**라고 한다
- `seq`는 기록을 하나 만들 때마다 1씩 늘어서 `fake-1`, `fake-2`... id가 겹치지 않게 한다
- **Java와 다른 점:** Java 람다는 바깥 지역 변수를 바꿀 수 없다(`effectively final`이어야 함). 그래서 Java로 쓰면 `AtomicInteger seq`를 쓰거나 클래스를 하나 만들어 필드로 둬야 한다. JS는 그냥 바꿀 수 있다

  ```java
  // Java로 쓴다면
  class FakeRecordFactory {
    private final String today;
    private int seq = 0;
    FakeRecordFactory(String today) { this.today = today; }
    HarvestRecord harvest(int houseNo, int daysAgo) { seq++; ... }
  }
  ```

- `cycleDays = DEFAULT_CYCLE_DAYS`: 기본값이 있는 인자다. `harvest(1, 40)`처럼 빼먹으면 35일, `harvest(17, 38, 40)`처럼 넣으면 그 값이다. 실제 입력 화면에서 "기본값이 채워져 있고 바꿀 수 있다"는 것과 같은 모양이다
- `=> ({ ... })`: 화살표 함수가 **객체를 바로 돌려줄 때는 괄호로 감싼다.** 괄호가 없으면 `{`를 함수 몸통의 시작으로 읽어 버린다
- `...base(houseNo, daysAgo)`: 공통 항목(id, 날짜, 입력자 등)을 펼쳐 넣고, 그 뒤에 종류별 항목을 덧붙인다. Vitest 노트의 테스트 도우미와 같은 방식이다
- `seq % 2 === 0 ? 'fake-father' : 'fake-brother'`: 삼항 연산자(Java와 같음). 입력자를 번갈아 넣는다. 4단계 이력 화면에서 쓸 값이다

### 취소와 수확량 예

```ts
const wrongHarvest = harvest(12, 3)
const yesterdayHarvest = harvest(5, 1)
...
yesterdayHarvest, harvestAmount(yesterdayHarvest, 3, 5), // 수확 후 1일
harvest(12, 37), wrongHarvest, cancel(wrongHarvest),     // 🟢 수확 후 37일
```

- 12번 동은 3일 전 수확을 잘못 입력했다가 취소한 상황이다. 취소가 제대로 되면 37일 전 수확을 기준으로 🟢가 뜬다. 취소가 안 되면 "수확 후 3일"이 뜬다
- 5번 동은 어제 수확하고 오늘 아침 수확량(3박스 5단)을 입력한 상황이다. 수확량은 아직 화면에 나오지 않는다 (4단계 이력 화면에서 보여줌)
- `cancel`과 `harvestAmount`는 동 번호 대신 **대상 기록**을 받는다. 대상 기록의 `id`를 `target_id`에, `house_no`를 그대로 쓴다

### 수확 중과 문제 예

```ts
harvest(2, 36), harvestStart(2, 0),        // 수확 중, 오늘 시작
harvest(19, 39), harvestStart(19, 1),      // 수확 중, 시작 후 1일 (아직 완료 안 함)
harvestStart(16, 1), harvest(16, 0),       // 오늘 수확 (어제 시작해 오늘 완료)
...
problem(7, 30, 'drainage'), problem(7, 10, 'mycelium'),              // 7번 동 💧🍄 둘 다
problem(20, 30, 'drainage'), problem(20, 5, 'drainage', true),       // 20번 동: 해결됨 → 배지 없음
```

- `problem(동, 며칠 전, 종류, resolved = false)`: 마지막 인자를 빼면 "생김", `true`면 "해결됨"이다. 기본값이 있는 인자라 `harvest`의 `cycleDays`와 같은 모양이다
- 20번 동은 배수 불량이 생겼다가 해결된 상황이다. 마지막 기록이 "해결됨"이라 배지가 없어야 한다
- 문제 기록이 없는 동(대부분)은 이상 없음이다

### id가 UUID가 아닌 이유

원래 규칙은 `crypto.randomUUID()`로 만든 UUID다. 그런데 이 기능은 폰에서 PC 개발 서버(`http://192.168...`)로 접속하면 막힌다. 가짜 데이터라 `fake-1`로 충분하다 → [[2026-10-22-Vite-개발-서버와-화면-확인]] 4번

## 8. `pages/HouseList.tsx`: 화면

문법은 [[2026-10-22-React-컴포넌트와-props]] 3번에서 거의 한 줄씩 설명했다. 여기서는 **순서**만 본다.

```
1. rows 만들기   동마다 { house, status }
                 status = getHouseStatus(records, house.no, today)
                        → kind(수확 중/🟢/⚪), 시작 후 일수, 수확 후 일수, 약 후 일수, readyDate, problems
2. 정렬         수확 중인 동이 맨 앞 → readyDate가 이른 순 → null(수확 기록 없음)은 뒤, 같으면 동 번호 순
3. zones 만들기  houses.ts에 나온 순서대로 구역 이름 목록
4. 그리기        구역마다 흰 카드 하나 → 그 구역의 rows만 골라서(filter) → 한 동 한 줄
```

- **수확 중인 동이 맨 앞이다.** 지금 손대고 있는 동이라 가장 먼저 보이게 했다. 비교 함수 맨 앞에서 "둘 중 하나만 수확 중이면 그쪽이 앞"을 먼저 가른다
- **그다음 정렬 기준은 수확 가능일(`readyDate`)이다.** 화면에는 안 보이지만, 이미 🟢인 동은 오래 기다린 동이 앞에 오고, 그다음 곧 🟢가 될 동이 온다. 수확 후 일수로 정렬하지 않은 이유: 17번 동처럼 동마다 `cycle_days`가 다르면 "수확 후 38일"이 "수확 후 36일"보다 늦게 🟢가 될 수 있기 때문이다
- **25동 전체를 먼저 정렬한 뒤 구역별로 나눈다.** 정렬된 배열에서 `filter`로 고르면 순서가 그대로 유지되므로, 구역 안에서도 정렬된 순서가 된다. 구역마다 따로 정렬할 필요가 없다
- 계산(`getHouseStatus`)은 `harvestCalc.ts`를 그대로 부른다. 화면은 계산 방법을 모른다
- `formatToday`: `"2026-10-22"` → `"10월 22일 (목)"`. 요일은 `new Date('2026-10-22T00:00:00Z').getUTCDay()`로 구한다 (0이 일요일). UTC로 읽어야 폰 시간대 때문에 요일이 하루 밀리지 않는다
- 안내 문구 "약 친 뒤 수확은 농약 포장 표기를 확인하세요"가 여기 있다 (`CLAUDE.md`)

### 작은 컴포넌트 `Elapsed`

```tsx
function Elapsed({ label, days }: { label: string; days: number }) {
  if (days === 0) return <>오늘 {label}</>
  return (
    <>
      {label} 후 <strong>{days}</strong>일
    </>
  )
}
```

"수확 후 30일"과 "약 후 2일"은 모양이 같아서 한 컴포넌트로 만들었다. 0일이면 "오늘 수확", "오늘 약"으로 쓴다. 숫자만 `<strong>`으로 크게 해서 한눈에 들어오게 했다.

- props 타입을 `interface` 없이 그 자리에 `{ label: string; days: number }`로 적었다. 이 파일 안에서만 쓰는 작은 컴포넌트라 이름을 붙이지 않았다
- 컴포넌트 안에서 `if`로 일찍 `return`할 수 있다. Thymeleaf에서 `th:if`/`th:unless`로 두 갈래를 쓰는 것과 같다
- `<>...</>`는 **프래그먼트**다. 화면에는 아무 태그도 남기지 않고 안의 글자만 넣는다. 이 컴포넌트는 글자만 만들고, 그 글자를 감싸는 `<p>`는 부르는 쪽이 정한다. 그래서 수확 줄은 굵게(`house-main`), 약 줄은 작고 회색으로(`house-sub`) 같은 컴포넌트를 다르게 꾸밀 수 있다. Thymeleaf의 `<th:block>`과 같다 (태그 없이 내용만 남김)

### 한 동 한 줄의 구조

```
<li class="house-row">
  <span class="house-no">6<small>동</small></span>
  <div>
    <p class="house-main">수확 후 <strong>38</strong>일</p>    ← 수확 중이면 "시작 후 N일", 수확 기록이 없으면 회색 "수확 기록 없음"
    <p class="house-sub">약 후 <strong>2</strong>일</p>        ← 약 기록이 있을 때만
  </div>
  <span class="badge badge-ready">수확 가능</span>            ← 🟢일 때만 (수확 중이면 진한 초록 "수확 중")
  <div class="house-tags">                                    ← 문제가 있을 때만
    <span class="badge badge-problem">🍄 균사 많음</span>
  </div>
</li>
```

화면에서는 이렇게 놓인다. 3칸짜리 격자(grid)이고, 문제 배지는 둘째 줄에 동 번호 칸을 빼고 넓게 놓는다.

```
[6동] [수확 후 38일       ] [수확 가능]
      [약 후 2일          ]
      [🍄 균사 많음                  ]
```

- **가운데 첫 줄은 세 갈래 중 하나다.** 수확 중이면 "시작 후 N일"(당일은 "오늘 시작"), 수확 기록이 있으면 "수확 후 N일", 없으면 회색 "수확 기록 없음". 삼항 연산자를 이어서 쓴다

  ```tsx
  {status.daysSinceHarvestStart !== null ? (
    <p className="house-main"><Elapsed label="시작" days={status.daysSinceHarvestStart} /></p>
  ) : status.daysSinceHarvest !== null ? (
    <p className="house-main"><Elapsed label="수확" days={status.daysSinceHarvest} /></p>
  ) : (
    <p className="house-main is-empty">수확 기록 없음</p>
  )}
  ```

  `A ? X : B ? Y : Z`는 Java의 `if (A) X else if (B) Y else Z`와 같다. `&&`는 "있으면 그리고 없으면 안 그림", `? :`는 "둘 중 하나를 그림"이다
- "시작 후"에는 앞에 "수확"을 붙이지 않았다. 오른쪽에 "수확 중" 배지가 있어서 뜻이 통하고, 360px 폰에서 "수확 시작 후 1일"은 한 줄에 들어가지 않는다
- **문제 배지는 `status.problems`에서 읽는다.** `house`(고정 정보)가 아니라 기록에서 계산한 값이다
- **문제 배지에 글자를 붙였다.** 처음에는 💧🍄 이모지만 동 번호 밑에 두었는데, 무슨 뜻인지 바로 알기 어렵고 폰에서 작게 보였다 → [[결정기록]] "문제 표시는 아이콘에 글자를 붙인다"
- 이모지에는 `aria-hidden="true"`를 붙였다. 화면 읽기 기능(시각 장애인용)이 "물방울 배수 불량"처럼 이모지 이름까지 읽지 않고 "배수 불량"만 읽게 한다
- 상태는 색만으로 구분하지 않고 **글자 배지**("수확 가능")를 쓴다. 햇빛 아래에서나 색약이면 색만으로는 구분이 어렵기 때문이다

## 9. `HouseList.css`, `index.css`: 모양

크기 단위는 [[2026-10-22-CSS-rem-단위]]에 있다. 여기서는 색과 줄 배치를 본다.

### 색: CSS 변수

```css
/* index.css: 색은 이름을 붙여 한 곳에 모은다 */
:root {
  --bg: #f2f4f6;            /* 바탕 (연회색) */
  --surface: #ffffff;       /* 카드 */
  --text-sub: #4e5968;      /* 보조 글자 */
  --primary: #12a150;       /* 주 색 (초록) */
  --primary-weak: #e3f6ea;  /* 옅은 초록 바탕 */
  --warn-weak: #fff1e0;     /* 문제 배지 바탕 (옅은 주황) */
  ...
}

/* HouseList.css: 이름으로 가져다 쓴다 */
.badge-ready {
  background: var(--primary-weak);
  color: var(--primary-strong);
}
```

- `--primary`처럼 `--`로 시작하는 것은 **CSS 변수**다. `var(--primary)`로 꺼내 쓴다. Java의 상수 클래스(`Colors.PRIMARY`)와 같다. 주 색을 바꾸려면 `index.css` 한 곳만 고치면 된다
- 이름을 "초록"이 아니라 **역할**(`primary` 주 색, `warn` 주의)로 붙였다. 나중에 주 색을 다른 색으로 바꿔도 이름이 틀려지지 않는다
- 보조 글자(`--text-sub`)를 너무 옅게 하지 않았다. 옅은 회색은 깔끔해 보이지만 아버지가 읽기 어렵다
- 밝은 화면 하나만 쓴다(`color-scheme: light`). 폰이 다크 모드여도 밝게 나온다

### 줄 배치: CSS Grid

```css
.house-row {
  display: grid;
  grid-template-columns: 2.8rem 1fr auto;   /* [동 번호] [가운데] [배지] */
  align-items: center;
  gap: 0.4rem 0.5rem;                       /* 줄 사이 0.4rem, 칸 사이 0.5rem */
}

.house-tags {
  grid-column: 2 / -1;                      /* 2번째 칸부터 끝까지 차지 */
}
```

- `grid-template-columns`: 칸 너비를 왼쪽부터 정한다. `2.8rem`은 고정, `1fr`은 남는 폭 전부, `auto`는 내용(배지)만큼
- `grid-column: 2 / -1`: 이 항목은 2번째 칸 선부터 마지막 선(`-1`)까지 걸친다. 그래서 문제 배지는 동 번호 칸을 빼고 가운데와 오른쪽을 합친 넓이를 쓴다. 칸이 3개라 이 줄은 자연히 다음 줄로 내려간다
- HTML의 `<table>`에서 `colspan`으로 칸을 합치는 것과 비슷하다. 다만 표가 아니라 그냥 `<li>` 안의 항목을 칸에 맞춰 놓는 것이다
- `.house-row + .house-row { border-top: ... }`: **바로 앞에 같은 줄이 있는 줄**에만 위 구분선을 긋는다. 그래서 구역 카드의 첫 줄 위에는 선이 없다
- `.house-main`에 `white-space: nowrap`: 360px 폭 폰에서 "수확 후 40일"이 두 줄로 갈라져서 한 줄로 고정했다
