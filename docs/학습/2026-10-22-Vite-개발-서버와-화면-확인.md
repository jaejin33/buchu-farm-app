# Vite 개발 서버와 화면 확인

앱 2단계에서 만든 화면을 직접 띄워 보고 끄는 법이다. Spring Boot 앱을 `bootRun`으로 띄워 본 입장에서 정리한다.

## 1. 대응표

| 이 프로젝트 | Spring Boot | 하는 일 |
|---|---|---|
| `npm run dev` | `./gradlew bootRun` | 개발 서버 실행 |
| `http://localhost:5173` | `http://localhost:8080` | 기본 주소 |
| 저장하면 화면이 바로 바뀜 (HMR) | `spring-boot-devtools`의 자동 재시작 + LiveReload | 코드 고친 걸 바로 확인 |
| `npm run build` | `./gradlew bootJar` | 배포용 파일 만들기. 결과는 `dist/` 폴더 |
| `npm run preview` | `java -jar app.jar` | 배포용으로 만든 결과물을 띄워 확인 |
| 터미널에서 **Ctrl + C** | 터미널에서 Ctrl + C | 서버 끄기 |

`npm run 이름`은 `package.json`의 `scripts`에 적힌 명령을 실행한다. → [[2026-10-22-Vitest-테스트와-순수-함수]] 0번

## 2. 켜고 끄기

**`package.json`이 있는 프로젝트 폴더에서 실행한다.** PowerShell을 새로 열면 보통 사용자 폴더(`C:\Users\...`)에서 시작하므로 먼저 이동한다.

```powershell
cd C:\dev\buchu-farm-app
npm run dev
```

다른 폴더에서 실행하면 `Missing script: "dev"`나 `package.json`을 찾을 수 없다는 에러가 난다. Spring에서 `build.gradle`이 없는 폴더에서 `./gradlew bootRun`을 치면 안 되는 것과 같다.

터미널에 이렇게 나온다.

```
VITE v8.3.5  ready in 216 ms
➜  Local:   http://localhost:5173/
➜  Network: use --host to expose
```

- `Local` 주소를 브라우저에서 연다
- 끌 때는 **그 터미널에서 Ctrl + C**를 누른다. Windows에서 "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`
- **`npm stop`은 없는 명령이다.** `package.json`에 `stop` 스크립트가 없어서 `Missing script: "stop"` 에러가 난다

### Claude Code 안에서 `!`로 띄웠을 때

Claude Code 프롬프트에서 `! npm run dev`로 띄우면 서버가 뒤에서 돈다. 이때는 Ctrl + C가 서버까지 닿지 않는다. 끌 때는 Claude에게 "서버 꺼 줘"라고 하거나, 처음부터 따로 연 터미널에서 띄운다. **따로 연 터미널에서 띄우는 쪽을 추천한다.**

### "Port 5173 is in use, trying another one..."

이미 5173 포트에서 서버가 돌고 있다는 뜻이다. 이전에 띄운 서버를 안 끄고 또 띄웠을 때 나온다.

- Spring Boot는 이럴 때 `Port 8080 was already in use` 에러를 내고 **멈춘다**
- Vite는 **에러 없이 다음 번호(5174)로 띄운다.** 그래서 모르는 사이에 서버가 여러 개 돌 수 있다

이 메시지가 보이면 예전 서버가 어디서 돌고 있는지 찾아서 끄는 게 좋다. 브라우저로 5173을 보고 있었다면 예전 서버의 화면을 보고 있었을 수도 있다.

## 3. PC에서 폰 화면 크기로 보기

이 앱은 폰에서 쓴다. PC 브라우저 창 그대로 보면 화면 폭이 넓어서 글자가 줄바꿈되는 위치나 배지 자리가 실제 폰과 다르다.

1. 브라우저에서 **F12** (개발자 도구)
2. **Ctrl + Shift + M** (기기 툴바)
3. 위쪽 목록에서 "Galaxy S20" 같은 기종을 고른다

Spring 쪽에는 대응하는 게 없다. 브라우저의 기능이라 Thymeleaf 화면을 볼 때도 똑같이 쓸 수 있다.

## 4. 진짜 폰으로 보기 (같은 와이파이)

```
npm run dev -- --host
```

- `--` 뒤에 쓴 것은 npm이 아니라 Vite에 넘기는 옵션이다. `--host`는 "내 PC 밖(같은 와이파이의 폰)에서도 접속하게 열어 달라"는 뜻이다
- 터미널에 `Network: http://192.168.x.x:5173` 주소가 나온다. 폰 브라우저에 그 주소를 입력한다
- Windows 방화벽 창이 뜨면 "허용"을 누른다. **창이 안 뜨고 폰에서 안 열리면** 예전에 만들어진 Node.js 차단 규칙이 있는 것이다. 시작 메뉴 "방화벽을 통해 앱 허용" → "설정 변경" → Node.js JavaScript Runtime의 **개인**에 체크한다 (공용은 체크하지 않음)
- 폰은 PC와 **같은 공유기**에 연결돼 있어야 한다 (회사 손님용 와이파이는 보통 분리돼 있음)
- Spring Boot는 기본으로 밖에서도 접속할 수 있게 열린다. Vite는 기본으로 내 PC에서만 접속할 수 있고 `--host`를 붙여야 열린다
- 캡처나 F12 기기 툴바로 보는 화면은 폰과 비율은 같지만, 손에 들고 보는 느낌(글자가 작게 느껴지는지 등)은 진짜 폰으로 확인해야 안다
- **날짜 칸처럼 브라우저가 직접 그리는 입력 칸은 PC와 폰에서 모양이 다르다.** 기록 입력 화면의 날짜가 폰에서만 두 줄로 꺾였다 → [[2026-10-23-날짜-칸-덮기와-클릭-이벤트-전파]]

**주의: http 주소에서 막히는 기능.** 이렇게 `http://192.168...`로 접속하면 브라우저가 "안전하지 않은 주소"로 본다. 그러면 기록 id를 만드는 `crypto.randomUUID()`, 5단계 PWA의 오프라인 기능(서비스 워커) 같은 일부 기능이 막힌다. `localhost`와 `https://` 주소에서만 동작한다.

- 기록 id는 3단계에서 해결했다. `crypto.randomUUID()`가 없으면 http에서도 되는 `crypto.getRandomValues()`로 같은 형식의 UUID를 직접 만든다 → [[결정기록]] "기록 id: http에서는 직접 UUID를 만든다", [[2026-10-22-3단계-코드-읽기]] 3번
- 폰에서 기록을 저장하면 그 폰 브라우저의 `http://192.168.x.x:5173` 주소 아래에 저장된다. PC 브라우저(`localhost`)의 기록과는 따로다 → [[2026-10-22-IndexedDB와-Dexie]] 2번
- PWA 기능은 5단계에서 다시 본다 (확인 필요)

인터넷 어디서나 링크로 여는 건 7단계(Vercel 배포)부터다. Vercel 주소는 `https://`라 위 문제가 없다.
