# 날짜 칸 덮기와 클릭 이벤트 전파

기록 입력 화면의 날짜 칸(`src/pages/RecordForm.tsx`, `RecordForm.css`)을 고치면서 나온 내용이다. 폰에서 날짜가 두 줄로 꺾였고, 고친 뒤에는 "바꾸기"를 눌러도 반응이 없었다. 그다음에는 PC에서 날짜 상자를 눌러도 반응이 없었다. 세 문제를 차례로 고치며 쓴 방법을 정리한다. 이 프로젝트에서 어떻게 쓰였는지는 [[2026-10-22-3단계-코드-읽기]] 7번 "날짜".

## 1. 브라우저가 그리는 입력 칸은 마음대로 못 고친다

`<input type="date">`는 HTML 태그 하나지만, 그 **안쪽**(날짜 글자, 달력 아이콘, 눌렀을 때 뜨는 달력)은 **브라우저가 직접 그린다.** 그래서:

- 폰마다 모양이 다르다. 안드로이드 크롬, 삼성 인터넷, 아이폰 사파리가 모두 다르게 그린다
- PC 크롬과 폰 크롬도 다르다. 그래서 PC로 폰 크기(F12 기기 툴바)를 흉내 내 확인해도 이 문제는 안 보였다
- CSS로 바깥 테두리·크기는 바꿀 수 있지만, 안쪽 글자가 어떻게 줄을 바꾸는지까지는 거의 손댈 수 없다

우리 앱은 글자가 크다(기준 20px). 좁은 폰에서는 브라우저가 그리는 `2026. 10. 22.`와 달력 아이콘이 칸에 다 안 들어가 두 줄로 꺾였다. 칸을 넓혀도 그대로였다.

Spring으로 치면 Thymeleaf로 `<input type="date">`를 내보내는 것까지는 서버가 정하지만, 그 칸이 화면에 어떻게 보이는지는 사용자의 브라우저가 정하는 것과 같다. 서버 쪽에 대응하는 개념은 없다.

## 2. 해결: 보이는 것은 직접 그리고, 진짜 칸은 투명하게 덮는다

```tsx
<div className="text-input date-field" onClick={openDatePicker}>
  <span>{formatDate(workDate)}</span>          {/* "10월 22일 (목)" ← 앱이 그림 */}
  <span className="date-change">바꾸기</span>
  <input ref={dateInputRef} id="work-date" type="date" value={workDate} ... />   {/* 투명 */}
</div>
```

```css
.date-field {
  position: relative;      /* 기준 상자 */
}
.date-field input {
  position: absolute;      /* 기준 상자 위에 겹쳐 놓기 */
  inset: 0;                /* 위·오른쪽·아래·왼쪽 모두 0 → 상자 전체 덮기 */
  width: 100%;
  height: 100%;
  opacity: 0;              /* 안 보이게 */
}
```

- **보이는 글자**는 앱이 `formatDate`로 만든 "10월 22일 (목)"이다. 우리가 그리니 꺾이지 않게 정할 수 있다 (`white-space: nowrap`)
- **진짜 날짜 칸**은 그대로 두고 투명하게 위에 겹친다. 누르면 폰의 달력이 원래대로 열리고, 고른 날짜는 `onChange`로 들어온다. 날짜를 고르는 기능은 브라우저 것을 그대로 쓴다

### 겹쳐 놓기: `position: relative` + `absolute`

- `position: relative`인 상자 안에서 `position: absolute`인 항목은 **그 상자를 기준으로** 위치를 잡는다. 다른 항목의 자리를 차지하지 않고 위에 떠 있다
- `inset: 0`은 `top: 0; right: 0; bottom: 0; left: 0`을 한 번에 쓴 것이다. 네 변을 모두 상자 끝에 붙여서 상자 전체를 덮는다
- HTML 표로 비유할 게 없어서 그림으로 보면 이렇다

  ```
  ┌ div.date-field (relative) ─────────────┐
  │ 10월 22일 (목)                  바꾸기 │  ← 보이는 층
  │┌ input (absolute, 투명) ──────────────┐│
  ││                                      ││  ← 위에 떠 있는 투명한 층 (누르면 이게 눌림)
  │└──────────────────────────────────────┘│
  └────────────────────────────────────────┘
  ```

### 왜 `opacity: 0`인가

안 보이게 하는 방법은 여럿인데, **누를 수 있어야** 해서 `opacity: 0`을 썼다.

| 방법 | 보이나 | 자리 차지 | 누를 수 있나 |
|---|---|---|---|
| `display: none` | ✗ | ✗ | ✗ (없는 것과 같음) |
| `visibility: hidden` | ✗ | ○ | ✗ |
| **`opacity: 0`** | ✗ | ○ | **○** |

## 3. 폰 브라우저의 버릇

### 너비를 고집한다

PC 크롬은 투명한 칸에 `width: 100%`를 주면 상자 전체를 덮었다. 그런데 폰에서는 **날짜 글자 쪽은 눌리고 "바꾸기"는 안 눌렸다.** 투명한 칸이 왼쪽 일부만 덮고 있었던 것으로 보인다. 일부 폰 브라우저(특히 아이폰 사파리)는 날짜 칸에 자기가 정한 너비를 고집한다.

```css
.date-field input {
  min-width: 100%;          /* 너비를 최소 100%로 강제 */
  -webkit-appearance: none; /* 브라우저 기본 모양을 끔. 그래야 위 너비가 먹는다 */
  appearance: none;
}
```

- `appearance: none`: "브라우저가 정한 기본 모양을 쓰지 마라"는 뜻이다. 기본 모양을 끄면 보통 태그처럼 CSS 너비를 따른다
- `-webkit-`이 붙은 것은 사파리·옛 크롬용 이름이다. 같은 설정을 두 이름으로 적었다

### 16px보다 작은 칸을 누르면 확대한다

아이폰은 글자가 16px보다 작은 입력 칸을 누르면 읽기 쉽게 화면을 확대한다. 아버지 입장에서는 갑자기 화면이 커져 당황할 수 있다. 그래서 투명한 칸도 `font-size: 1rem`(20px)으로 두었다.

## 4. 그래도 덮지 못하면: 상자를 누르면 직접 달력 열기

CSS만으로 모든 폰에서 덮는다는 보장이 없어서, **상자 어디를 눌러도** 코드로 달력을 연다.

```tsx
function openDatePicker(e: MouseEvent<HTMLDivElement>) {
  const input = dateInputRef.current
  if (input === null) return
  const inputClicked = e.target === input
  if (inputClicked && !window.matchMedia('(pointer: fine)').matches) return   // 폰: 브라우저가 이미 엶
  try {
    input.showPicker()       // 달력 열기
  } catch {
    if (inputClicked) return // 아래 click()이 다시 여기로 와서 끝없이 도는 것을 막음 (5번)
    input.focus()            // showPicker가 없는 옛 브라우저
    input.click()
  }
}
```

- `showPicker()`: 날짜 칸의 달력을 코드로 여는 브라우저 기능이다. 최근 브라우저에 있다. PC 크롬은 원래 달력 아이콘을 눌러야만 열리는데, 이걸로 어디를 눌러도 열린다
- 없는 브라우저에서 부르면 에러가 나므로 `try` / `catch`로 감쌌다 (Java와 같음). 그때는 날짜 칸을 누른 것처럼(`focus()` + `click()`) 한다
- 사람이 누른 직후에만 열 수 있다. 화면이 뜨자마자 저절로 달력을 여는 것은 브라우저가 막는다 (광고 창을 막는 것과 같은 이유)
- `const inputClicked = e.target === input`: `===`는 "같은가"다 (Java의 `==`처럼 같은 객체인지 본다). 결과(`true`/`false`)를 이름 붙여 두고 두 번 쓴다

## 5. PC와 폰은 날짜 칸을 누를 때 하는 일이 다르다

| | 날짜 칸(글자 부분)을 누르면 | 달력 아이콘을 누르면 |
|---|---|---|
| 폰 (안드로이드 크롬, 아이폰 사파리) | 달력이 열린다 | (아이콘이 따로 없거나 같음) |
| PC 크롬 | 연·월·일 중 한 칸에 커서만 간다. **달력은 안 열린다** | 달력이 열린다 |

우리 앱은 투명한 날짜 칸이 상자 전체를 덮는다. 그래서 PC에서는 달력 아이콘도 투명해서 안 보이고, 상자를 누르면 "글자 부분"이 눌린다. 처음 코드는 투명한 칸이 눌리면 "브라우저가 이미 열었다"고 보고 아무것도 안 했다. 그래서 **폰에서는 잘 되는데 PC에서는 눌러도 반응이 없었다** (Vercel 배포 뒤 PC로 열어 보고 찾음).

### 마우스 기기인지 묻기: `matchMedia('(pointer: fine)')`

```ts
window.matchMedia('(pointer: fine)').matches   // 마우스면 true, 손가락(터치)이면 false
```

- `matchMedia`는 CSS의 미디어 조건(`@media (...)`)을 코드에서 물어보는 기능이다. `.matches`가 `true`/`false`를 돌려준다
- `pointer: fine`은 "정밀하게 가리키는 도구(마우스, 터치패드)"라는 뜻이다. 손가락은 `pointer: coarse`(거친 도구)다
- 화면 폭으로 PC와 폰을 나누지 않은 이유: 폭은 "얼마나 넓은가"이지 "무엇으로 누르는가"가 아니다. 여기서 궁금한 것은 누르는 도구다

그래서 지금 코드는 이렇게 동작한다.

| 눌린 곳 | 폰 | PC |
|---|---|---|
| 투명한 날짜 칸 (상자 대부분) | 그대로 둠 (브라우저가 엶) | 우리가 `showPicker()` |
| 날짜 글자·"바꾸기"·여백 (투명한 칸이 못 덮은 곳) | 우리가 `showPicker()` | 우리가 `showPicker()` |

폰도 늘 우리가 열게 하면 코드가 더 단순하다. 하지만 그러면 브라우저가 연 달력을 우리가 한 번 더 여는 셈이 된다. 폰마다 어떻게 될지 몰라서, 진짜 폰에서 확인한 동작은 건드리지 않았다.

### F12 기기 툴바에서는 안 열릴 수 있다

F12 → Ctrl + Shift + M(폰 크기 보기)을 켜면 PC 크롬이 **손가락 기기인 척**을 한다. 그러면 `pointer: fine`이 `false`가 되어 코드는 "폰이니 브라우저에 맡기자"고 한다. 그런데 실제로 날짜 칸을 그리는 것은 PC 크롬이라 달력을 열지 않는다. 진짜 폰과 PC 보통 화면은 둘 다 열린다. 폰 크기 보기에서 날짜를 바꿔야 하면 키보드로 숫자를 입력하거나 진짜 폰으로 확인한다.

Spring 쪽에는 대응이 없다. 서버는 누가 어떤 도구로 눌렀는지 모른다 (요청 헤더의 User-Agent로 기종을 짐작할 수는 있지만, 누르는 도구까지는 알 수 없다).

## 6. 클릭 이벤트 전파 (버블링)

위 코드에서 `e.target === input`(투명한 칸이 직접 눌렸나)을 왜 따지는지가 이 노트의 두 번째 개념이다.

### 클릭은 바깥으로 퍼진다

HTML에서 태그를 누르면, 그 태그에서 `click` 이벤트가 생기고 **감싸고 있는 바깥 태그로 차례로 전해진다.** 거품이 위로 올라가는 것 같다고 해서 **버블링**이라고 부른다.

```
투명한 날짜 칸(input)을 누름
  → input의 click         (브라우저가 달력을 엶)
  → div.date-field의 click  ← 우리 onClick도 불린다!
  → section의 click
  → ... → document
```

그래서 투명한 칸이 눌려도 바깥 상자의 `openDatePicker`가 불린다. 그대로 두면 브라우저가 연 달력을 우리가 또 열려고 한다.

### `e.target`과 `e.currentTarget`

| 이름 | 뜻 | 이 경우 |
|---|---|---|
| `e.target` | **처음 눌린** 태그 | 투명한 칸을 눌렀으면 `input`, "바꾸기"를 눌렀으면 `span` |
| `e.currentTarget` | **지금 이 함수가 달린** 태그 | 항상 `div.date-field` |

폰에서 `e.target === input`이면 "투명한 칸이 직접 눌려서 브라우저가 이미 달력을 열었다"는 뜻이라 아무것도 안 한다. 그 밖(날짜 글자, "바꾸기", 여백)이 눌렸을 때만 우리가 연다. PC는 5번처럼 둘 다 우리가 연다.

### 무한 반복도 막는다

옛 브라우저(`showPicker`가 없음)에서는 `catch`에서 `input.click()`을 부른다. 이 클릭도 버블링으로 다시 `div`의 `openDatePicker`에 온다. 이때 `e.target`은 `input`이다.

- 폰: 맨 위 `if (inputClicked && 폰) return`에서 멈춘다
- PC: 그 줄을 지나 `showPicker()`를 또 부르고, 또 에러가 나서 `catch`로 온다. 여기서 `if (inputClicked) return`으로 멈춘다

이 멈추는 줄이 없으면 "click → openDatePicker → input.click() → click → openDatePicker → ..."가 끝없이 반복된다. 처음에는 맨 위 줄 하나로 둘 다 막았는데, PC에서도 달력을 열게 고치면서(5번) PC 쪽이 뚫려서 `catch` 안에 한 줄을 더 넣었다.

### Java·Spring에서는

Spring(서버)에는 대응하는 개념이 없다. 화면 이벤트는 브라우저 안에서만 일어난다.

Java Swing에서는 안쪽 컴포넌트가 마우스 이벤트를 받으면(리스너가 달려 있으면) 그 이벤트가 바깥 패널로 전해지지 않는다. 버튼의 `ActionListener`도 그 버튼에서만 불린다. HTML은 반대로 **기본이 전파**다. 안쪽에서 처리해도 바깥까지 계속 전해진다. 전파를 멈추고 싶으면 `e.stopPropagation()`을 부른다. 우리는 멈추지 않고 `e.target`으로 누가 눌렸는지 보고 거르는 쪽을 택했다. 이렇게 하면 투명한 칸이 어디까지 덮든 같은 함수 하나로 처리된다.

```java
// Swing으로 굳이 흉내 내면: 안쪽 컴포넌트에서 받은 마우스 이벤트를 바깥에 직접 넘겨야 한다
inner.addMouseListener(new MouseAdapter() {
    public void mouseClicked(MouseEvent e) {
        outer.dispatchEvent(SwingUtilities.convertMouseEvent(inner, e, outer));
    }
});
```

## 7. `:focus-within`

```css
.date-field:focus-within { border-color: var(--primary); }
```

`:focus`는 "그 태그가 눌려 있을 때(입력 중일 때)"다. `:focus-within`은 "**안에 있는** 태그 중 하나가 그럴 때"다. 투명한 날짜 칸은 눈에 안 보이므로, 그 칸이 선택되면 바깥 상자에 초록 테두리를 그려 다른 입력 칸과 같은 느낌을 준다.

## 8. 확인하는 법

- PC 크롬(F12 기기 툴바)으로는 **폰의 날짜 칸 모양과 달력을 볼 수 없다.** 꺾임과 "바꾸기" 문제는 진짜 폰에서만 보였다
- 반대로 PC에서만 보이는 문제도 있다. 날짜 상자가 PC에서 안 눌린 것(5번)은 폰으로는 안 보였다
- 폰으로 보기: Vercel 주소를 폰에서 연다 ([[2026-10-23-https와-Vercel-자동-배포]]). 같은 와이파이에서 `npm run dev -- --host`로 볼 수도 있다 ([[2026-10-22-Vite-개발-서버와-화면-확인]] 4번)
- 브라우저가 그리는 칸(날짜, 시간, 고르기 목록 `<select>` 등)을 고친 뒤에는 진짜 폰과 PC 보통 화면 둘 다 확인한다
